# Webレイアウト：用語の分類（4つの軸）

親: [[01_engineering/00 MOC|common/01_engineering]]

「single column / two column / grid / Z-pattern / hero / masonry …」は**同じ軸の選択肢ではない**。
軸を分けて考えると、1ページに複数の名前が同時に付く理由がわかる。

| 軸 | 決めること | 代表的な用語 |
|---|---|---|
| **A. 骨格** | 画面を何個の領域にどう分けるか | Single / Two / Three column, Split screen, Holy grail, Grid, Masonry, Bento |
| **B. 配置スタイル** | 骨格の上でどんな雰囲気に並べるか | Magazine, Asymmetrical, Broken grid, Centered, Card |
| **C. 視線の流れ** | 読み手の目がどう動くか | Z-pattern, F-pattern, Gutenberg diagram, Layer cake |
| **D. ページ・セクションの型** | ページ全体／一部の役割 | Hero, Full screen, Landing page, Dashboard, One-page scroll |

> [!tip] 考え方
> 「どれか1つを選ぶ」ではなく「**各軸で1つずつ選ぶ**」。
> 例：LP = 1カラム（A）+ Hero（D）+ Z型（C）+ Centered（B）

---

## A. 骨格：領域をどう分けるか

実装では CSS Grid / Flexbox の使い方に対応する軸。

### Single column（1カラム）
```
┌────────────┐
│   ┌────┐   │
│   │    │   │
│   ├────┤   │
│   │    │   │
│   └────┘   │
└────────────┘
```
- 縦に1本流す。スマホの基本形で、記事・LP・ブログに多い
- 視線が迷わず、モバイルファースト設計と相性が良い
- 弱点：PC の広い画面だと余白が余る（最大幅 `max-width` を決めて中央寄せにする）

### Two column（2カラム）
```
┌────────────┐
│ ┌──────┬──┐│
│ │ main │si││
│ │      │de││
│ └──────┴──┘│
└────────────┘
```
- メイン + サイドバー。ブログ・ドキュメント・管理画面で定番
- モバイルでは1カラムに折り返す（サイドは下に回す／折りたたむ）

### Three column（3カラム）
- 左ナビ + 本文 + 右目次／広告。ドキュメントサイトやニュースサイト向け
- 情報量は多いが、狭い画面では必ず崩れるため折り返し設計が必須

### Split screen（スプリットスクリーン）
```
┌─────┬──────┐
│     │      │
│ img │ text │
│     │      │
└─────┴──────┘
```
- 画面を左右ほぼ50:50に割り、それぞれ独立した内容を置く
- 「写真 + コピー」「ログイン画面（左ビジュアル／右フォーム）」「2つの選択肢の対比」に使う
- 二択の導線（例：個人向け／法人向け）にも向く
- 2カラムとの違い：サイドバーのような「従」ではなく、**対等な2領域**

### Holy grail（聖杯レイアウト）
```
┌────────────┐
│   header   │
├───┬────┬───┤
│ L │main│ R │
├───┴────┴───┤
│   footer   │
└────────────┘
```
- ヘッダー + 3列（中央が可変・両脇が固定）+ フッター
- 昔は float や table で実現が難しく「聖杯」と呼ばれた。今は Grid で素直に書ける
- 実装の目安：`grid-template-columns: 200px 1fr 200px`

### Grid（グリッド）
```
┌────────────┐
│ ▢  ▢  ▢   │
│ ▢  ▢  ▢   │
│ ▢  ▢  ▢   │
└────────────┘
```
- 同じ大きさのマス目に等間隔で並べる。商品一覧・ギャラリー・カード一覧
- 実装：`grid-template-columns: repeat(auto-fill, minmax(240px, 1fr))` でレスポンシブになる
- 注意：「grid layout」は**見た目の分類**でもあり**CSS Grid という技術**でもある。区別して話す

### Masonry（メイソンリー）
```
┌────────────┐
│ ▢  ▢▢ ▢   │
│ ▢▢ ▢  ▢   │
│ ▢  ▢▢ ▢▢  │
└────────────┘
```
- 列幅は揃え、**高さが不揃い**のカードを隙間なく詰める（石積みの意味）。Pinterest 型
- 画像のアスペクト比がバラバラなときに向く
- Grid との違い：行を揃えないので、縦方向に「上から詰まる」
- 実装：JS ライブラリ、または CSS columns で近似。CSS ネイティブの masonry は標準化の途中でブラウザ対応にばらつきがある（導入前に確認）

### Bento grid（ベントーグリッド）
```
┌────────────┐
│ ▓▓▓▓ │ ▒▒ │
│ ▓▓▓▓ ├────┤
│──────┤ ▒▒ │
│ ▒▒ │ ▓▓▓▓ │
└────────────┘
```
- 弁当箱のように、**大小のセルを組み合わせて**1つの面を埋める
- Grid の発展形（セルが複数行・列にまたがる）。Apple 系の機能紹介ページで広まった
- 機能紹介・ダッシュボード風のLPに向く。重要な機能ほど大きいセルにする

### 参考：Sidebar / Sticky 系
- **Fixed sidebar**：サイドバーを固定して本文だけスクロール（管理画面）
- **Sticky header**：スクロールしてもヘッダーが追従する

## B. 配置スタイル：骨格の上での「見せ方」

骨格（A）の内側を、どんな思想で並べるか。内部の実装は Grid であることが多い。

### Magazine（マガジン）
```
┌────────────┐
│ ┌────────┐ │
│ │ 大写真  │ │
│ └────────┘ │
│ ▌▌ ▌▌ ▌▌   │
└────────────┘
```
- 雑誌のように、大きな写真 + 段組み + 見出しのサイズ差で**読ませる**
- 読み物・メディア・特集記事向け。見出し階層（大／中／小）を強くつけるのがコツ

### Asymmetrical（非対称）
```
┌────────────┐
│ ▓▓▓▓▓  ▒▒ │
│ ▓▓▓▓▓  ▒▒ │
│ ▒▒▒▒▒  ▓▓ │
└────────────┘
```
- あえて左右のバランスを崩して**動き・個性**を出す
- ブランドサイト、ポートフォリオ向け。崩しても**余白と整列の基準線**は残さないと散らかる

### Broken grid（崩れたグリッド）
- グリッドの上に、画像や文字を意図的に**はみ出す・重ねる**
- Asymmetrical の強い版。実装は `grid` + 負のマージンや `transform`、`z-index` の重ね
- 見栄えは強いが、モバイルで崩れやすい。モバイルでは通常の1カラムにフォールバックさせる

### Centered（中央揃え）
- 全要素を中央軸で揃える。LP・サービス紹介で多い
- 長文には不向き（行頭が揃わず読みにくい）。短いコピーやCTA中心なら安定する

### Card（カード）
- 情報を「カード」という単位で区切って並べる
- 配置というより**部品の考え方**。Grid・Masonry の中身としてよく使う

## C. 視線の流れ：読み手の目はどう動くか

レイアウトの「種類」ではなく、**視線の理論**。設計時に重要要素をどこに置くかの根拠になる。

### Z-pattern（Zパターン）
```
①──────────▶②
              ╱
            ╱
          ╱
③──────────▶④
```
- 左上（ロゴ）→ 右上（ナビ）→ 斜めに左下 → 右下（CTA）の順に見る
- **情報量が少ない**ページ向け。LP・ヒーロー周辺。④に CTA ボタンを置く

### F-pattern（Fパターン）
```
①━━━━━━━━━━━━▶
②━━━━━━▶
┃
┃
▼
```
- 上の横線 → やや短い2本目の横線 → 左側を縦に流し読み
- **文章量が多い**ページ向け（記事・検索結果）。見出しや要点は左に寄せる、各段落の冒頭に結論を置く

### Gutenberg diagram（グーテンベルクの図）
- 画面を4分割し、**左上（起点）→ 右下（終点）** へ視線が流れるとする考え方
- 右上・左下は「弱い領域」。均質で文字中心のページに当てはまる
- Z-pattern のベースになっている理論

### Layer cake（レイヤーケーキ）
- 見出しをつなげて**斜め読み**する閲覧パターン。見出しが明確なら読み飛ばされず伝わる
- 見出しだけ読んで内容が伝わるように書く

### 補足
- Z / F はどちらも**傾向**であって法則ではない。画像・色・動きがあれば視線は簡単に変わる
- 設計では「パターンに合わせて置く」より「ヒートマップやユーザーテストで検証する」ほうが確実

## D. ページ・セクションの型：役割による分類

骨格・スタイル・視線を**組み合わせる対象**。

### Hero（ヒーロー）
- ページ最上部の大きなビジュアル領域（見出し + サブコピー + CTA + 画像）
- **ページ全体ではなくセクションの名前**。ファーストビューで価値を伝えるのが役割
- パターン：画像背景／動画背景／左テキスト・右画像／中央テキストのみ

### Full screen（フルスクリーン）
- 1セクションが `100vh`（画面全体）を占有する見せ方
- 1画面1メッセージで強く見せる。Hero に使うことが多い
- 注意：スマホのアドレスバーで高さが変わる問題がある。`100dvh` の使用を検討する

### Landing page（ランディングページ）
- 広告や検索から**最初に着地**するページ。1つの行動（問い合わせ、購入）に絞った縦長の構成
- 典型的な流れ：Hero → 課題 → 解決策 → 実績・事例 → 料金 → FAQ → CTA
- 「Landing page」は**ページの目的による分類**で、見た目の分類（A〜C）とは別軸

### One-page / Scroll（ワンページ）
- 1ページに全情報を縦に並べ、アンカーリンクで移動する構成
- LP とほぼ同じ形だが、LP は目的の名前、One-page は構造の名前

### Dashboard（ダッシュボード）
- 数値・グラフ・一覧を1画面に集約。Bento 風の Grid + 固定サイドバーが定番
- 業務システム・管理画面向け

### Parallax / Scroll storytelling
- スクロールに合わせて背景や要素が動く演出。ブランド紹介・特集向け
- 見栄えは強いが、重さ・アクセシビリティ（動きの苦手な人への配慮）に注意

## 組み合わせの例

| ページ | A 骨格 | B 配置 | C 視線 | D 型 |
|---|---|---|---|---|
| サービスLP | Single column | Centered | Z-pattern | Landing page + Hero |
| ブログ記事 | Two column | Magazine | F-pattern | — |
| 機能紹介ページ | Bento grid | Card | Z-pattern | Hero + Full screen |
| 管理画面 | Holy grail | Card | F-pattern | Dashboard |
| 画像ギャラリー | Masonry | Card | — | — |
| ログイン画面 | Split screen | Centered | — | Full screen |
| ポートフォリオ | Grid | Asymmetrical | Z-pattern | One-page scroll |

## 使い分けの目安

1. **まず D（目的）**：何のページか。LP か、記事か、管理画面か
2. **次に A（骨格）**：情報量と端末（スマホ中心か PC 中心か）で決める
3. **C（視線）で要素の置き場所を決める**：重要要素・CTA をどこに置くか
4. **最後に B（スタイル）**：ブランドの雰囲気に合わせて崩す・整える
