# 4.4.3 整数計画ソルバーの利用

← [[4.4.2_切除平面法]] | ↑ [[しっかり学ぶ数理最適化_MOC]] | → [[4.5_近似解法]]

## 整数計画ソルバーの現状

- 分枝カット法を探索の基本戦略とする **整数計画ソルバー**（整数計画問題を解くソフトウェア）の進歩は著しく、実務に現れる大規模な整数計画問題が次々と解かれている。商用・非商用を含めて多くのソルバーが公開され、数理最適化以外の分野でも急速に普及。
- 4.2.2節のとおり多くの組合せ最適化問題はNP困難だが、計算の複雑さの理論が示す結果の多くは「最悪の場合」であり、多くの問題例では現実的な計算手間で最適解を求められる。ソルバーは探索中に得られた暫定解を保持しているため、最適解を求められなくても質の高い実行可能解が求まれば十分な事例も多い。
- 商用ソルバーはライセンス料が必要だが、無償の試用ライセンスや教育研究向けの安価なアカデミックライセンスが提供されている場合も少なくない。一般に非商用より商用の方が性能は高いが、商用の中でもかなりの性能差がある。性能以外にも、あつかえる問題の種類注101、記述形式、インターフェースなどを考慮して選ぶことが望ましい。
- 注101：最近では非線形の整数計画問題をあつかえるソルバーも増えている。

## 利用方法

例題：

$$
\begin{aligned}
\text{最大化}\quad & 2x_1 + 3x_2 \\
\text{条件}\quad & 2x_1 + x_2 \le 10, \\
& 3x_1 + 6x_2 \le 40, \\
& x_1, x_2 \in \mathbb{Z}_+.
\end{aligned}
\tag{4.143}
$$

主な利用方法：
1. コマンドラインインターフェースを通じてソルバーを実行する方法
2. 最適化モデリングツールを通じてソルバーを実行する方法
3. プログラミング言語のライブラリやソフトウェアのプラグインを通じてソルバーを実行する方法

### (1) LP形式・MPS形式

**LP形式**注102による記述例（図4.75）：

```
maximize
 obj: 2 x1 + 3 x2
subject to
 c1: 2 x1 + x2 <= 10
 c2: 3 x1 + 6 x2 <= 40
bounds
 x1 >= 0
 x2 >= 0
general
 x1 x2
end
```

- 目的関数や制約条件の部分は数式をほぼそのまま表しているだけ注104。`maximize`, `subject to`, `bounds`, `general`, `end` は予約語で、目的関数、制約条件、変数の範囲、整数制約の有無などを記述する。文法が平易で可読性が高く、多くのソルバーが対応。
- 注102：LPは linear programming の略。
- 注104：図4.75では非負制約を表しているが、LP形式では何も指定しなければ各変数の非負制約 $x_j \ge 0$ は自動的に設定される。

**MPS形式**注103による記述例（図4.76）：1960年代にIBMにより導入された形式で、現在も標準的に使われているが可読性は低い。

```
NAME          sample
ROWS
 N  obj
 L  c1
 L  c2
COLUMNS
    INTSTART  'MARKER'                 'INTORG'
    x1        obj            -2   c1             2
    x1        c2              3
    x2        obj            -3   c1             1
    x2        c2              6
    INTEND    'MARKER'                 'INTEND'
RHS
    RHS       c1             10   c2            40
BOUNDS
 PL Bound     x1
 PL Bound     x2
ENDATA
```

- 注103：MPSは mathematical programming system の略。
- LP形式やMPS形式はプログラミング言語のように変数をまとめて表せない。$\sum_{j=1}^{100} x_j \le 3$ を記述するには `x1 + x2 + ... + x100 <= 3` と書くしかない。大規模な問題例では入力データをLP形式やMPS形式に変換するプログラムを作成する必要がある。

### (2) モデリング言語

最適化モデリングツールが提供するモデリング言語で記述し、ツールを通じてソルバーを実行する。記述例（図4.77）：

```
param n, integer;
param m, integer;
param c{j in 1..n};
param a{i in 1..m, j in 1..n};
param b{i in 1..m};
var x{j in 1..n}, integer >= 0;

minimize z: sum{j in 1..n} c[j]*x[j];
s.t. con{i in 1..m}: sum{j in 1..n} a[i,j]*x[j] <= b[i];

data;
param n := 2;
param m := 2;
param c := 1 -2, 2 -3;
param a: 1 2 :=
   1  2 1
   2  3 6;
param b := 1 10, 2 40;
end;
```

- モデルとデータを分離して記述できるため、数式を容易にモデルに書き換えられる。$\sum_{j=1}^{n} a_{ij}x_j \le b_i$ は `sum{j in 1..n} a[i,j]*x[j] <= b[i]` と書ける。現実問題を定式化できればすぐにソルバーを利用できるので効率的なプロトタイピングが可能。一方、ツールにより言語の仕様が異なるため1番目の方法に比べ汎用性に欠ける。

### (3) ライブラリ・プラグイン

- 部分問題を解くサブルーチンとしてソルバーを利用する場合や、ソルバーの挙動を細かく制御したい場合に効率的。ただしソルバーやバージョンにより仕様が異なるため汎用性と保守性に欠ける。

## 計算が終了しない場合の診断

- ソルバーは分枝カット法を基本戦略とするため、大規模でも効率的に解ける問題例がある一方、いつまで待っても解けない小規模な問題例があり、変数や制約条件の数だけでは計算時間を見積もれない。
- 分枝カット法は子問題に分割しつつ、暫定解から得られる下界（最小化なら上界）と線形計画緩和問題から得られる上界（最小化なら下界）を利用した限定操作で無駄な探索を省く。計算が終了しないなら以下が原因として考えられる（ソルバーは他にも多くのアルゴリズムを内包するため決めつけるべきではないが、まず確認すべきこと）：
  1. 線形計画緩和問題の求解に多大な計算時間を要する
  2. 限定操作が効果的に働いていない

### (1) 線形計画緩和問題の求解時間

- 整数制約を取り除いた線形計画問題をソルバーで解けば見積もれる。実際にはソルバーは双対単体法による再最適化で効率化するため子問題での求解時間はさらに短くなる。線形計画問題を1回解くのに要する時間が長いようであれば、問題例の規模がソルバーで解くには大きすぎると判断するのが妥当。

### (2) 限定操作が効果的に働かない原因注105

- (i) 暫定解から得られる最適値の下界（最小化なら上界）が悪い
- (ii) 線形計画緩和問題の最適解から得られる最適値の上界（最小化なら下界）が悪い
- (iii) 多数の最適解が存在する
- 注105：ソルバー実行時には最適値の上界と下界が表示されるが、差が大きい場合には(i)と(ii)のどちらにあたるのか容易に判断がつかないことが多い。

**(i) の対策**：実行可能解が非常に少ないか存在しないため良い実行可能解を見つけられないことが原因と考えられる。必ず満たさなければならない制約条件（**絶対制約**）とできれば満たしてほしい制約条件（**考慮制約**）に分類し、優先度の低い制約条件を緩和する。例：$\sum_{j=1}^{n} a_{ij}x_j \ge b_i$ を $\sum_{j=1}^{n} a_{ij}x_j \ge b_i - \varepsilon$（$\varepsilon$ は適当な正の定数）に置き換える方法や、新しい変数 $s_i\ (\ge 0)$ と重み係数 $w_i\ (> 0)$ を導入して $\sum_{j=1}^{n} a_{ij}x_j + s_i \ge b_i$ に置き換えた上で目的関数に違反度を表す項 $w_is_i$ を加える方法。利用者の先験的な知識で実行可能解を容易に求められるならば、初期の暫定解としてソルバーに与えることも可能。

**(ii) の対策**：線形計画緩和問題の実行可能領域は整数格子点をすべて含む凸多面体であるため、同じ整数計画問題に対して緩和問題の最適値が異なる複数の定式化が存在する（図4.78）。最適値の良い上界（最小化なら下界）が得られる **強い定式化** と、そうではない **弱い定式化** が存在する。制約条件の少ない定式化の方が見栄えも良く緩和問題の求解時間も短くなるように思われるが、上界と下界の差が広がれば子問題の数は急激に増加するため安易に制約条件を減らすべきではない。多くのソルバーは冗長な制約条件を前処理で取り除くため、制約条件が多少増えても計算時間にはあまり影響しないことが多い。完全単模行列（4.1.6節）に近い形の制約行列を持つ定式化ができれば良い上界が期待できる。

- 図4.78（整数計画問題の実行可能解をすべて含む複数の多面体の例）：同じ整数格子点集合を含む大きさの異なる2つの凸多角形が重ねて描かれ、目的関数の方向に対して緩和問題の最適解の位置が異なる。

**(iii) の対策**：上界と下界の差が小さいにもかかわらず終了しないなら多数の最適解を持っている可能性がある。目的関数や制約条件を変更して最適解の数を減らす。例：ビンパッキング問題の定式化（4.20）は使用する箱の組合せを問わないため多数の最適解が生じる。添字 $i$ の数字が小さい箱から順に使用するという制約条件を追加すると減らせる：

$$
y_i \ge y_{i+1},\quad i = 1, \ldots, n-1.
\tag{4.144}
$$

多目的最適化問題の定式化（2.23）を1変数からなる目的関数を持つ整数計画問題に変換するとやはり多数の最適解が生じる。この場合はすべての目的関数の最大値ではなく重み付き和を最小化する定式化に変更した方が良い注106。目的関数 $\sum_{j=1}^{n} c_jx_j$ の各係数 $c_j$ がすべて同じ値をとる場合も多数の最適解が生じやすいため、可能なら異なる値に設定する。

- 注106：ただし、すべての目的関数をバランス良く最小化することが難しくなるので一長一短。

## 最適解をあきらめる選択

- いつまで待っても終了しない場合には最適解を求めることをあきらめるのも1つの手。ソルバーは探索中の暫定解を保持しているため、質の高い実行可能解が求められれば十分に満足できる場合も多い。
- ソルバーは発見的解法としても高性能であり、メタヒューリスティクス（4.7節）などを利用・開発する前に、ソルバーを適用して質の高い実行可能解を求められるかどうか確認すべき。
