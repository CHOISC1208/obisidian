# 5.2 ユーザビリティ要件の明確化

← [[5.1_非機能要件の明確化]] | ↑ [[要件定義のセオリー_MOC]] | → 第6章 [[6.1_アーキテクチャ方針の明確化]]

前項の非機能要件を基に、「機能・UI 要件の明確化」で作成したプロトタイプ（ペーパープロトタイプ）と画面遷移に対し、ユーザビリティの観点から見直しを掛けることでユーザビリティ要件を明確化する。

## ユーザビリティの明確化の目的

- 情報システムにおけるユーザビリティ ＝ **画面 UI の使い勝手**。非機能要件の一つ
- 作り手（目的：データ操作、効果：定量効果）／使い手（目的：心地よさ・使い勝手、効果：感動・安心）。**「使い手」の各項を明確化する** ことが本項の目的
- 「機能・UI 要件の明確化」ではユーザー（関係者かお客様か、エンタープライズ系かコンシューマー向けかを問わず）にデータ操作を円滑に行ってもらうための UI を明かした（作り手側の論理）。本項では **使い手側の論理、真のお客様視点** で UI を再整理し、ユーザビリティの観点から必要な UI を明確化
- 画面遷移を含めてユーザビリティを高めるべくきちんと時間をかけて検討することは、システムの価値を高める上で充分に価値のある作業

## 「わかりやすく」「速い」こと

- 特にコンシューマー向け Web では「わかりやすく」「速い」ことが重要。「速い」はユーザビリティではなくレスポンスの話だが、使い勝手を考えると無視できない。**両立できてはじめて「良いシステム」**
- 両立を意識した UI 検討が必要。時には妥協も（例：1ページに情報を集約して一覧性を重視するより、読み込みスピードを優先して複数ページに分割）
- UI は **より「シンプルに考える」方が両立が可能**。一度できるところまでシンプルに、余計なものを全部削ぎ落としてみるくらいの気概が必要

## 最近の UI トレンド

- コンシューマー向け：スマートフォン普及・SNS の影響で **「縦」位置の画面が標準** になりつつある。PC の横長画面に慣れた文化が変わりつつあり、ユーザビリティ検討では縦長画面を考慮
- スマートフォン（特に iPhone）普及に伴い、ユーザーは心地よく操作できることを当たり前に求める。指に吸い付くように画面遷移できることが当然。そうした世の中の「当たり前」を頭に入れてユーザビリティを考える
- エンタープライズ系：従来コンシューマー向けと比べ求められるユーザビリティは低いと言われてきたが状況は変わりつつある。**「働きやすさ」** が企業組織の指針になり、優秀な人員確保の条件になっている。社内に閉じられたシステムを社外スタッフに開放する機会も増え、当初想定より多くの人の目に触れ操作される。機能によっては一時期の「チープな UI」では通用しない。「働きやすさ」を支援する「使いやすさ」とともにさらなる効率性が求められる
- 従来従業員しか触れなかったシステムを一般のお客様が操作するようになった。コンシューマー向けとエンタープライズ系の境界線が曖昧になりつつある今、改めてエンタープライズ系がユーザビリティと向き合うべき時

## UX の観点からユーザビリティを見直す

- 「わかりやすさ」とともに UX で忘れてはならないのは **「一貫性があること」**。画面 UI ごとにばらばらの印象ではユーザーは心地よく安心して操作できない
- 本来は画面設計標準を参照して UI を作れば自然に実現できる環境を構築すべきだが、ここは **UI に特化した標準** を用意し遵守することで「わかりやすさ」と「一貫性」を高める
- 複数の異なるデバイスに関しても考慮。PC で操作し続けてスマートフォンで操作した際にも何の支障もなく継続できるように。ただし必要なのは **「一貫性」であって決して「同一性」ではない**

## ペルソナの再定義

- より **シビアなペルソナ** を作り上げてユーザビリティを見直す。「シビア」＝ コンシューマー向けなら「満足すれば良いお客様になってもらえるが、その壁が高いユーザー」、エンタープライズ系なら「該当機能を使い倒すくらいに使い込むヘビーユーザー」
- 本来は設計工程で行うべき作業だが、**「競争力の源泉」** となりうるものを早い段階できちんと整理することは重要かつ不可欠
- 再定義したペルソナの視点でペーパープロトタイピングを行う。カスタマージャーニーマップも必要なら作成・修正。例：「アニメーションを効果的に追加する」、レスポンス優先のため「一部ページの読み込みを少なくする」等の意見が出る

## 手順：「ユーザビリティ要件の明確化」

1. **ペルソナの再定義**：定義し作り上げたペルソナ像を見直し、システム形態を問わず「厳しい」ユーザー像を作り上げる。改めて **データを元に** 実際のユーザー像の思考・言動・行動を想定して作り上げる（エンタープライズ系なら部署・職位・能力（評価）等、コンシューマー向けなら年齢層・性別・行動履歴等）
2. **プロトタイプの見直し**：ペーパープロトタイプをペルソナの視点で見直し、必要があれば修正。必要と思われるデザインの追加も検討し、内容をプロトタイプの横に書いておく
3. **画面遷移の見直し**：ペーパープロトタイプを並び替えて画面遷移を再度見直し、改めて明確化
4. **ペルソナの視点からの見直し**：ペルソナの視点から最低限抑えるべき事項を忘れずにプロトタイプに反映。留意すべき事項があれば書き出す
5. **プロトタイプ、画面遷移の確定**：ユーザビリティ要件を反映したプロトタイプと画面遷移を確定
6. **非機能要件定義書の作成**：このプロトタイプ等を含め、非機能要件定義書の一部としてまとめる
