# しっかり学ぶ数理最適化

梅谷俊治『しっかり学ぶ数理最適化 モデルからアルゴリズムまで』（講談社 KS情報科学専門書, 2020-10）。
**第1章〜第4章の本文を章別ノート93本**にして [[しっかり学ぶ数理最適化_MOC]] 配下に置いた（2026-09-15）。
読書会の場としては未開催で、**現時点では個人の読了ノート**。巻末の演習問題の解答例と用語一覧は未取り込み。

## 本の要点

- 数理最適化は **定式化 → アルゴリズムによる求解 → 計算結果の分析・検証 → 問題とアルゴリズムの再検討** の反復（1.1節）
- 最適化問題は **定数・変数・制約条件・目的関数** の4要素で書き、変数・目的関数・制約条件の種類で問題クラスが決まる（1.2〜1.3節）
- **緩和問題と双対問題が全編を貫く中心概念。** 最適値の上界・下界を与え、感度分析・双対単体法・整数計画の限定操作まで同じ道具で説明される（2.3節）
- 非線形計画は **凸かどうか**が効率的に解けるかの分かれ目。最適性条件（KKT条件）を出発点にアルゴリズムが並ぶ（3.1〜3.3節）
- 整数計画の価値は**定式化の型を知っていること**にある。論理条件・固定費用・離接制約・パターン列挙といった型で現実問題が書ける（4.1節）
- 組合せ最適化は **難しさの評価（NP困難）→ 素直に解ける問題（貪欲法・動的計画法・ネットワークフロー）→ 厳密解法（分枝限定法・切除平面法・ソルバー）→ あきらめ方（近似解法・局所探索法・メタヒューリスティクス）** の順に整理されている（4.2〜4.7節）

## 自社への当てはめ

- **4.1節の定式化パターン集は、MOSS の「要求 → 定式化」でそのまま辞書として使える。** 論理的な制約条件（4.1.2）・固定費用付き目的関数（4.1.3）・離接した制約条件と big-M（4.1.4）・集合分割／集合被覆によるパターンの列挙（4.1.8）は、現場の言葉（「この設備を動かすなら段取りの費用がかかる」「同時にはできない」「組み合わせのパターンから選ぶ」）を式に落とすときの定番の受け皿になる（[[MOSS AIチャットモードの対話設計]] の対話4段で聞き出す内容の受け皿）
- **感度分析（2.3.4）と双対変数は「なぜこの解なのか」を現場に説明する材料。** 最適化の結果をそのまま出すのではなく、どの制約が効いているか・係数がどこまで変わっても解が変わらないかを添える形は、MOSS のような内製プラットフォームで信頼を得るための説明の型になる（[[MOSS システム概要]]）
- **「整数性を持つ整数計画問題」（4.1.6）は案件の難易度見積りに直結する。** 最短路・割当・ネットワークフローに落ちる問題は緩和が整数解を持つので素直に解けるが、そこから外れると解けなくなる。テーマの初期ヒアリングで**規模と構造を聞く理由**がここにある（[[DIテーマ MOC]] のテーマ立ち上げ時）
- **[[4.4.3_整数計画ソルバーの利用]] は本書でいちばん実務にそのまま持ち込める節。** 「ソルバーが終わらない」ときの診断が手順になっている（まず線形計画緩和問題を1回解いて求解時間を見る → 限定操作が効かない3原因を切り分ける）。とくに次の2つは案件の進め方に直結する
  - **絶対制約と考慮制約に分けて、優先度の低い制約は緩和して違反度を目的関数に入れる。** 「実行可能解が出ない」と言われたときに現場と交渉すべき対象がこれで決まる
  - **同じ問題に強い定式化と弱い定式化があり、制約条件を安易に減らすと遅くなる。** 「式を簡単にしたのに遅くなった」の説明がつく
- **「最適解をあきらめる選択」の順序も実務の型として使える。** メタヒューリスティクスを作る前に、まずソルバーで質の高い実行可能解が出るかを確認する（4.4.3節）。そのうえで足りなければ 4.5〜4.7 に移る、という順序は内製プラットフォームの実装方針としてそのまま使える（[[MOSS システム概要]]）
- **学会で見た発表の読み解きに効く。** 配船計画の構造化（[[ORSJ2026秋_1-H-5_化学業界配船計画構造化]]）や立会者手配（[[ORSJ2026秋_1-H-6_工事立会者手配最適化民主化]]）のような発表は、4.1節の定式化の型と 4.4〜4.7 のアルゴリズム（厳密解法／近似解法／局所探索／メタヒューリスティクス）のどこに位置するかで整理できる（[[学会 MOC]]）
- **テーマの難易度の言葉を揃えられる。** [[4.2.2_問題の難しさとNP困難問題]] の「実務的な見方」と [[4.3_効率的に解ける組合せ最適化問題]]（最短路・割当・フローに落ちるか）は、「このテーマは素直に解けるのか」を部門内で同じ言葉で話すための土台になる（[[DIテーマ MOC]]）
- **1.1節の反復の手続きは、検証ログの単位そのもの。** 「定式化を変えた／アルゴリズムを変えた」を1回の反復として記録すると、後から何を試したかが辿れる（[[検証ログ MOC]]）
- **[[要件定義のセオリー]] と役割が対になる。** あちらは「要求を要件に落とす」工程の本、こちらは「要件を式に落とす」本。数理最適化案件では両方が続きの工程として必要になる

## 使えそうなテーマ

1. **MOSS の定式化テンプレに 4.1節の型（論理条件・固定費用・離接制約・集合分割）を定型の受け皿として入れる** — 試すなら `04_knowledge/検証ログ/` にログを起こす
2. **最適化結果の説明に感度分析を添える型を作る** — どの制約が効いているかを必ず1枚に出す
3. **[[4.4.3_整数計画ソルバーの利用]] の診断手順を「ソルバーが終わらないときのチェックリスト」に起こす** — 絶対制約／考慮制約の切り分けと、強い定式化への直し方を案件で使える形にする
