# 監訳者あとがき

← [[もっと深く学ぶために]] | ↑ [[INSPIRED_MOC]]

監訳者（佐藤真治・関満徳、2019年10月）によるあとがき。**日本の読者に向けた文脈**を与えている。

## シリコンバレーにおけるプロダクトマネジメントの歴史

- **源流を探るとHewlett-Packard（HP）にたどり着く。HPは1938年の創業後、40年間にわたって年20%を超える成長率を維持したシリコンバレーの老舗。**
- **創業者のヒュレット氏とパッカード氏の考え方は「HP Way」と呼ばれ、HP社員の行動指針だったが、その後、シリコンバレーにおけるマネジメントの基本として認知されるようになった。**
- **特徴的だったのは、製品ごとに担当のグループを設け、そのグループにその製品に関する開発、製造、販売を含む、すべてのプロセスの責任を持たせたこと。そして、一つのグループが500人を超えると、強制的に分割することによって、製品のマネジメントができるようになっていた。**
- **この地域がシリコンバレーと呼ばれるようになるのは70年代に入ってから。** シリコン半導体の実用化 → トランジスターの進化 → 集積回路の普及 → マイクロプロセッサの開発と急激な産業化 → **パーソナルコンピュータという一大ビジネス**。
- **80年代以降のシリコンバレーでは、品質の高い製品・サービスを出荷することは重要だったが、企業は顧客に訴求することがビジネスにとって最も重要であることに気がつき始めた。**
- **特に、ソフトウェア、インターネットサービスに価値創造の中心が移行するにつれ、製品やサービスの内容は成熟度を増し、その結果、顧客中心の製品開発の重要性が叫ばれるようになった。**
- **企業はマーケティングやブランディング部門を強化し、その活動で得られた顧客のニーズを製品に注入すべく、プロダクトマネジメントという手法が大きな注目を浴びるようになった。**
  - **Intelは「Intel Inside」（日本では「インテル入ってる」）というタグラインでハイテク業界にブランディングの重要性を知らしめた。**
  - **GoogleはOKRなど、プロダクトマネジャーを中心とした製品開発の手法を磨いた。**
  - **社長であるスティーブ・ジョブズ自らがプロダクトマネジャーとして活躍したAppleは、モバイルコンピューティング市場を大きくリードした。**
- **今や、シリコンバレーで製品、サービスを提供しようとする企業にプロダクトマネジャーがいないということは考えられない。**

## 日本のプロダクトマネジメント

- **『Inspired』日本語版の第一版は2012年に出版されたが、それ以前の日本のIT業界でプロダクトマネジメントの必要性が大きく取り上げられることはなかった。それをよく知っていたのは、米国系IT企業で開発に関わっている方々に限られていた。**
- **一方、2000年代の初頭に米国のIT業界で急速に普及したアジャイル開発については、日本でもエンジニアを中心に徐々に導入されるようになっていた。製品の開発に関して、何らかの解決策を必要とし、模索していた時期なのかもしれない。**
- **監訳者は、日本のIT業界がプロダクトマネジメントの必要性を大きく認識した理由は、スマートフォンの普及によるモバイル市場の拡大だと考えている。**
  - **モバイルアプリは、その使用環境の特性から、特化した目的のために開発される必要がある。なぜなら、ユーザーがアプリを起動するとき、ほとんどのユーザーは何をしたいかがはっきりと決まっているから。**
  - **そのようなアプリは、ユーザーがやりたいことを最小限の努力で達成できるように、正確に設計されている必要がある。そうでなければ、ユーザーは途中で諦めてしまい、そのアプリを使わなくなってしまう。**
  - **以前のように、機能をたくさん詰め込むようなことは、絶対にしてはいけないこと。そこで、製品の開発を管理するためのプロダクトマネジメントの必要性が高まった。**
- **優秀なエンジニアがいるにも関わらず、日本の製品、サービスの品質が高まらなかったことが、長年、製品の企画、開発に関わってきた監訳者が Inspired を翻訳する大きな動機である。**
- **現状ではまだ、プロダクトマネジメントに関してはキャッチアップする段階にあるが、このような努力を続ければ、早晩、シリコンバレーに追いつくことができるはず。**

## Inspired のすすめ

- **米国内では、プロダクトマネジメントに関する書籍は数多く出版されてきた。ほとんどのものはプロダクトマネジメントの原則について、異なる切り口で議論をしている。**
- **その中で『Inspired』はハイテク業界に特化し、実際に使われている手法について具体的に解説しているという点でユニークな存在である。**
- **一度読み終わった後も、本書はすぐに手に取ることができる場所に置くことをお勧めする。**
- **具体的な使い方の例**: **製品ビジョンは、一度作ったらそのままで良いというものではなく、一定の期間や開発のサイクルごとに、市場からのフィードバックを元に見直し、調整を行うことが普通である。**
  - **その際、プロダクトマネージャーを中心としてブレインストーミングを行うことが多いが、第25章にリストされている製品ビジョンの原則を見えるところに貼っておくと有効。**（→ [[25_製品ビジョンの原則]]）
  - **参加者全員がそれを意識し、それに沿って議論することで、陥りやすい問題を避け、議論を早めに収束させ、以前からの変更点が明確になるから。**

## デジタル・エボリューションを乗り越えて

- **本書のプロダクトマネジメントはハイテク、特にIT業界に焦点を当てたものではあるが、その考え方、手法の多くは、他の産業においても適用することが可能である。**
- **現在、日本の産業はデジタル・エボリューションの荒波の中で、大きな変革を迫られている。生き残るためには、デジタル技術を最大限生かせるように、ビジネス全体をゼロから再構築する必要がある。単に、今までの枠組みの中に技術を埋め込むだけではうまくいかないことは明白。**
- **もしIT業界の人なら、デジタルの力をてこにして、改革の先頭を切ってほしい。おそらく、経営陣とたくさんの議論をすることが必要だろう。しかし、うまくいかなかったとしても、その努力をするだけの価値はある。**
- **そして、ビジネスを再構築する機会に恵まれたら、その時にこそ、プロダクトマネジメントの種を撒く。時間はかかるかもしれないが、きっと美しい花を見ることができる。**
- **デジタル化を軸とした改革は、会社を成長させるためのベストな方法の一つ。それを成功させるためには、ITの専門家でありながら、ビジネスの経験がある人が責任者となって、ビジネス改革を推し進めなければならない。**
- **会社が提供する製品やサービスをデジタル化の文脈の中で再考するとき、プロダクトマネジメントの原則が大きく役立つはず。**

## 実践する際に忘れないでほしいこと

1. **プロダクトマネジメントの原則は普遍的なものである。技術が変わり、市場が変わったとしても、それらの原則には大きな影響はない。本書が解説している原則を深く理解しておくことを強く勧める。**
2. **テクニックにこだわりすぎてはいけない。** テクニックを学んで実践していくことは素晴らしく、その経験を通してさらに進んだ製品を開発できるようになるが、**シリコンバレーの企業はそれぞれ自社独自のプロダクトマネジメントのテクニックを持っており、常に新しいやり方を模索している。おそらく、近いうちに新しい手法が大きく注目されるだろう。自分のチームにとって、さらに良い方法を模索することは大切なこと。**
3. **プロダクトマネジャーだけで製品、サービスを作り出すことはできない。** デザイナーやエンジニア、そして経営陣をはじめとして、**社内の多くの人々の協力を得る必要がある。そのためには、自分のチーム、そして組織全体にプロダクトマネジメントの考え方を知らせることが重要。**
   - **ぜひ本書を「共通の言語」として、プロダクトマネジメントの理解を深め、チームの活動を展開してほしい。メンバーで共通の認識をもって取り組むことは、製品やサービスの開発を成功させるためにも非常に有効である。**
4. **製品やサービスは、顧客がいてこそ成り立つ。** プロダクトマネジメントには客観的な顧客の分析が必要なことから、**著者は顧客、もしくは見込み客と頻繁に話すことを強く勧めている。**
   - **本当の顧客と話をすることは、情報を得るという目的を達成するだけでなく、自分たちの思い込みを防ぐという意味がある。顧客の話を頻繁に聞いていれば、自分の主観や思い込みが入り込む隙間を埋めることができる。**
   - **しかし、これを実践するのは意外に難しい。そこで、それが強制的に起こるような仕組みや決まりごとを自社に導入することが望まれる。**
