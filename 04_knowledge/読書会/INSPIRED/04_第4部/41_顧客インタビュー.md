# 第41章 顧客インタビュー

← [[40_プロフィールMicrosoftのマルティナ・ローチェンコ]] | ↑ [[INSPIRED_MOC]] | → [[42_コンシェルジュテストのテクニック]]

**本書で説明する最も基礎的なテクニック。** プロダクトマネジャーならすでに知っていて何度も使っているのが当然なので取り上げる必要はないかもしれないが、**実際にはそれほど実行されていない**。

- あるいは**顧客インタビュー自体はおこなわれていても、プロダクトマネジャーが同席していないために、得た知識が心底から理解されていなかったり、必要な深刻さで受けとめられていない**（→ [[33_製品発見の原則]] の原則10「共同学習が大切である」）。
- **すべてのプロダクトマネジャーにとって最も強力で重要なスキルの1つであり、多くのブレイクスルーとなる製品のアイデアの源になったり、ひらめきを生んだりしている。**
- **製品のアイデアを定性的にテストするテクニックの前提条件になっている。**
- **顧客インタビューにはさまざまな形があるので、実際には1つのテクニックではない。** くだけた雰囲気のものもきちんとした形式のものもあり、**ユーザーリサーチの方法論（著者が好きなものの1つはコンテキストインタビュー）に基づいたものもあるし、ただオフィスを出て知らなかったことを学ぶというものもある。**

## 常に理解しようと心がける4つのこと

- **顧客はあなたが考えていたような人たちか？**
- **顧客は本当にあなたが考えるような問題を持っているか？**
- **顧客は現在、その問題をどうやって解決しているか？**
- **顧客を自社製品に乗り換えさせるためには何が必要か？**

## 学習機会から最大限のものを引き出すヒント

| 項目 | 原文のアドバイス |
|---|---|
| **頻度** | **一定の間隔でおこなう。たまにやる、というような頻度ではいけない。最低限、毎週2、3時間は実施する** |
| **目的** | **インタビューの間にどうにかして何かを証明しようとしてはいけない。すぐに理解して学習することに専念する。このマインドセットは重要であり、誠実でなければならない** |
| **ユーザーや顧客の集め方** | **ターゲット市場の人々と優先的に話をする。約1時間が目安**（詳細はユーザビリティーテストのテクニックで述べられる） |
| **場所** | **顧客が普段暮らしている場所で会えれば最高。環境を観察するだけでもわかることがたくさんある。** だがどこか便利な場所やオフィスでもいい。**ビデオ通話を使うのはベストとは言えないが、まったくインタビューができないのと比べるとはるかにまし** |
| **準備** | **事前に、顧客がどんな問題を持っているかについての自分の考えを明確にし、それに対してどんなふうに同意したり反論したりするかを考えておく** |
| **誰が出席すべきか** | **3人で行くことを勧める。プロダクトマネジャーと、プロダクトデザイナー、開発チームのエンジニアのうちの1人**（通常は出席を希望するエンジニアの中でローテーション）。**（大概、インタビューの上手なやり方を訓練されている）デザイナーが主導し、プロダクトマネジャーはメモを取り、開発者はやりとりを見ているのが普通** |
| **インタビュー** | **自然で堅苦しくない雰囲気を作るように努め、質問は自由回答形式にし、今、相手が何をしているのかを知る**（何をしたいと思っているかも興味深いが、それは二の次） |
| **終わった後** | **仲間と報告をし合い、全員が同じことを見聞きし、同じことを学習したかどうかを確認する。インタビューの間に顧客に約束したことがあれば、忘れずに実行する** |

## インタビューの後に製品のアイデアを試す

- **著者は顧客インタビューの時間を使っていくつかの製品のアイデアを試してみるのも大好き**である（もちろん**鍵となる質問の答えを聞いたあとで**）。
- **インタビューが終わってもすぐに話を切り上げる必要はない。インタビューのあとに、最も新しい製品のアイデアのユーザーテストをすることができる。**
