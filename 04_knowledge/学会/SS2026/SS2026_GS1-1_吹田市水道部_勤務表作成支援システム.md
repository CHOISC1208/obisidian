# 自治体水道部門の勤務表作成支援システムの開発と実運用評価

> [!abstract] 一言で
> 吹田市水道部浄水室（14名）の勤務表をCP-SATで作成するシステムを開発・導入。作成時間12〜18時間→2〜3時間（約8割減）。
> 設計上の要点は3つ：①「勤務扱い」と「実働計上」を別変数に分ける ②月境界週の公休を正しく数えるため**計画期間全体を一括求解** ③厳密モデルが実行不能なら**週公休のみ緩和し不足箇所を提示する二段階求解**。

## 背景・動機
- 水道は災害・設備異常への即応が必要で土日祝を含め毎日人員確保。勤務表は現場運営の基盤業務
- 従来は表計算で手作業、1か月分に積算12〜18時間・暦日2〜3日。調整手順が担当者の経験依存で引継ぎ困難
- 看護師スケジューリング（夜勤・スキルミックスが論点）と異なり、**週公休管理・拠点配置・固定予定の重なり**が課題。自治体水道部門で実運用効果まで報告した例は少ない

## 問題設定
- 職員14名（係長以上8、常勤13、嘱託1）。本庁舎／分庁舎の配置、研修・出張・休暇等の固定予定、日別実働人数、週公休数、連続勤務、休日勤務の公平性を同時に扱う

| 区分 | 内容 | 扱い |
|---|---|---|
| 必要人数 | 平日は実働6名以上、土日祝・閉庁日は6名ちょうど | ハード |
| 管理職配置 | 係長以上を毎日1名以上実働、本庁舎側にも1名以上残す。2名体制推奨 | 混合 |
| 分庁舎勤務 | 毎日2名、連続割当禁止、回数平準化 | 混合 |
| 週公休 | 常勤2日、嘱託3日、非常勤4日（週起算日基準） | 二段階 |
| 固定予定 | 確定済み休暇・研修・出張・グループ会議 | ハード |
| 連続勤務 | 連続6日間の実働5日以下、7日連続表示禁止 | ハード |
| 公平性 | 祝日休・土日公休・分庁舎回数の平準化 | ソフト |

- **月境界問題**：週公休は週単位で評価されるので、月ごとに独立に作ると1週が2つの部分週に分断され、両方で公休2日を課してしまい過剰公休が発生

## 定式化の要点
- 集合：職員 I、日 D、係長以上 L⊆I、週 T（週起算日基準で7日刻み）
- 変数（全て0-1、職員i×日d）：w_id 勤務扱い／k_id 分庁舎勤務／e_id 実働計上
  - **k ≤ e ≤ w**：分庁舎勤務は勤務扱いかつ実働。研修・出張・休暇は「勤務扱いだが実働に算入しない」を表現できる
- 主なハード制約：Σ_i e_id ≥ n_d（必要人数）／Σ_{i∈L} e_id ≥ 1 かつ Σ_{i∈L}(e_id − k_id) ≥ 1（管理職）／Σ_i k_id = 2（分庁舎）／**Σ_{d∈A_it}(1 − w_id) = r_it**（週公休、完全な7日週のみ。固定予定日は公休候補から除外）
- ソフト：各評価項目jの未充足量 u_j（非負整数）に重み ω_j、min Σ ω_j u_j。最大−最小差や絶対偏差はCP-SATの max/min/abs 制約で記述（線形化すればMILPでも可、CP-SAT固有表現には依存しない）

## 何が難しいか
1. 固定予定が特定週に集中すると、必要人数・連続勤務制限・全員の週公休を同時に満たす解が存在しない
2. 全制約を一度にソフト化すると「不足0の緩和解」と「厳密モデルが実行可能だった解」の区別がつかない → 担当者が何を調整すべきか分からない
3. 月別帳票の業務慣行と、週単位で評価する制約のミスマッチ

## 工夫・アプローチ
- **二段階求解**：第1段階は週公休を含む全ハード制約を厳密に課して実行可能性判定。実行不能のときだけ第2段階へ：週公休制約(5)を r_it − s_it ≤ Σ(1−w) ≤ r_it に緩和（s_it：職員i・週tの公休不足スラック）、目的は M·Σs + Σω_j u_j（M=10^9）。**不足が出た職員・週・必要公休数・実際公休数・不足日数を確認用シートへ出力**
- **期間一括求解**：月境界週を一続きの7日として評価
- **後付け構成**：C#実装、入力は職員一覧・イベント・祝日CSV、出力は既存様式に近いExcel。クラウドや専用DB不要で表計算中心の運用にそのまま乗る
- 出力は勤務表だけでなく「週2公休確認」シート、グループ会議日が祝日等と重なった場合の振替候補シートも生成 → 結果をそのまま採用させず、担当者が要確認箇所を見て最終判断する設計

## 実験設定
- 2026年5〜12月（245日）の実運用データ、14名。約2.1万変数・約5.2万制約
- OR-Tools v9.14 CP-SAT、各段階600秒上限、8ワーカー。Core i7-1255U・64GBのWindows PC

## 結果・評価
- 実運用設定：第1段階が**177秒で最適解**、週公休不足なし
- 二段階の動作確認：グループ会議日を木曜→月曜（祝日が5日ある曜日）に変えた比較条件で、第1段階3.7秒で実行不能判定→第2段階244秒で最適。公休不足は延べ5日・1週に集中、職員・週単位で提示できた
- 月別分割との比較：境界6週のうち2週で延べ16日の過剰公休 → 一括方式では発生せず。「**月別帳票でも最適化の計画期間は月境界を越えて設定すべき**」
- 作成時間 12〜18h → 2〜3h（約8割減）。残時間は入力確認・妥当性確認・例外対応
- 今後：他組織への一般化検証、CP-SAT以外のソルバ比較、重み感度分析、入力変更時の安定性、手修正量の定量評価

## 実務への示唆
- **実行不能をどう業務に返すか**の具体解：「ハード制約を守った通常解」と「不足を含む調整要の代替案」を明確に区別し、不足箇所をピンポイントで提示する。全部ソフト化しない
- 「勤務扱い／実働計上」の分離は、出張・研修・会議など「いるけど数えない」を持つ人員計画全般に使えるモデリングパターン
- 帳票単位（月）と制約単位（週）がずれるときは計画期間を帳票より広く取る
- 小規模（14名・245日）でもCP-SATで数分。専用インフラなしのCSV→Excel後付け構成は自治体・中小規模現場向けの現実解
- 出力に「確認用シート」を添える設計は、最適化結果を鵜呑みにさせない意思決定支援の型
