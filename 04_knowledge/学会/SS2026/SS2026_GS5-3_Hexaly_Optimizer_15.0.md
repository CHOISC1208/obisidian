# DXを進化させる Hexaly Optimizer 15.0

> [!abstract] 一言で
> 国内代理店MSIによる Hexaly Optimizer（旧LocalSolver）15.0の紹介。DXで得た予測結果を経営に活かすには最適化が必要＝**OX（最適化トランスフォーメーション）**という位置づけ。
> Hexaly社サイトの事例（ソフトバンクLPG配送、パスコ敷島の全国SCM 3,200万変数を3分、東邦チタンの出荷バッチ200万バイナリ）と、速さの理由（1変数ずつのムーブ＋DAG差分評価、ejection chains）、モデリングの違い（非線形を直接記述、list/set/**interval**変数）を解説。

## 内容
### OXという主張
- メタバース・DXは生成AIと統計予測がベース。予測を利益にするには最適化を足す必要があり、これをOXと呼ぶ

### 事例（Hexaly社HPから抜粋）
| 事例 | 問題 | 規模・結果 |
|---|---|---|
| ソフトバンク | LPG配送：需要予測〜配送ルート統合。時間枠・勤務時間・容量・最低在庫・欠品回避 | 1,000顧客×1週間を数分で準最適化 |
| パスコ敷島 | 国内13工場・100供給拠点・26配送ハブ、数日間の生産・流通コスト最小化。1,000製品、90万注文/日 | 3,200万変数・100万制約・800万バイナリ・16目標を基本サーバで**3分**。従来MIPは20サブ問題に分解して低品質だったが一括で解けた |
| 東邦チタン | 海綿チタンのドラム充填・出荷バッチ設計（成分・質量が顧客仕様を満たす） | 最大200万バイナリ、非線形多目的、ラップトップで数分 |

### なぜ速いか（解法）
- 従来ソルバはシンプレクス・分枝限定で行列計算。Hexalyは**1回のムーブで意思決定変数1組だけ変更し、目的・制約を差分計算**。計算時間が問題規模に比例
- 実行可能性を保つムーブ：**ejection chains**（変数と制約のハイパーグラフ、k-Chains/k-Cycles でパッキング・カバリング型の改善）
- **DAG によるモデル解析・Lazy propagation**：子ノードが変化したときだけ1回評価。x < a < b が真で a が減る/b が増えるなら x の再評価を省略
- 非凸モデルの上界値計算により最適性ギャップを算出、中小規模は最適性証明も可能 → MIP/(MI)QP/(MI)NLPソルバと競合と主張

### モデリングの違い
- 連立一次方程式ではなく**プログラミング言語による自由な定式化**：非線形・統計関数・条件式・罰金関数を直接記述。x*y をそのまま書ける（McCormick不等式不要）
- 「中間変数」の概念がなく、意思決定変数と（中間）式を区別。手順：①意思決定変数定義 ②制約・目的を式で定義 ③外部I/O定義（データとモデルを完全分離）
- list / set / **interval** 変数。15.0で interval(開始, 終了, 長さ, 含む) 演算子を追加 → JSP, FJSP, セットアップ付きFJSP, RCPSP を簡潔に記述
- 配車ルート：1,000配送を1分以内でほぼ最適。事前割当・相互排除・サイト制限・優先順位・積替・分割配送・労働時間コストに対応強化
- 製品群：Optimizer / Modeler / Studio / Cloud

### 主張（これからの最適化）
- プランニング（LP/MIP/NLP、全社規模・多目的）、スケジューリング（大規模組合せ）、オペレーション（人間＋AI）
- 要件：大規模、非線形、時間軸を持った即時性
- 「スケジューリング実用化の鍵は担当者の暗黙知の形式化。ヒアリングの精度と定式化力が重要」

## 実務への示唆
- 「MIPで分解しないと解けない全社規模の計画を、局所探索ベースのソルバで一括で解く」選択肢の存在と規模感（数千万変数・数分）。Gurobi/CBC で詰まったときの比較候補
- interval 変数のようなスケジューリング専用モデリング（CP Optimizer の interval と同系統）は、定式化の工数を大きく減らす
- ただし局所探索ベースなので**最適性保証は限定的**。厳密性が必要か、実用解が速く欲しいかで使い分け
- 事例はベンダー公開情報の転記。導入検討では第三者の比較（例：OR学会での比較報告）を探すべき
