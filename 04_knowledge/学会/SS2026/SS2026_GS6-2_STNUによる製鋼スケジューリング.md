# STNUを用いた所要時間の変動に対応する製鋼スケジューリングの検討

> [!abstract] 一言で
> 製鋼→二次精錬→連続鋳造（SCC）では輸送時間の上下限・キャスト連続鋳造など**時間制約**が厳しく、処理時間が少し延びるだけでスケジュールが破綻する。頻繁なリスケジュールは現場負荷が高い。
> そこで設備割当・順序は変えず「開始時刻と待機時間の調整だけ」で全時間制約を守れることを **STNUの動的制御可能性（DC）** で保証し、その中で**最悪メイクスパン**が最小のスケジュールをCP生成→DC判定→負閉路から禁止制約追加の反復で探索。全1200例でDC達成、比較法より%Best 82〜100%。

## 背景・動機
- SCCは生産全体のボトルネック。チャージ（取鍋の溶鋼単位）の順序・設備・開始時刻を決める。輸送時間 [τmin, τmax]、同一キャストは同一連鋳機で途切れなく、異キャスト間は段取りσ
- 変動対応の既存アプローチ：①リスケジューリング（大変動には有効、軽微な変動には過負荷）②ロバストスケジューリング（余裕時間を事前配置するが制約充足は保証されず、余裕を実行時に使う**実行戦略**が検討不足）

## 問題設定
- チャージ i∈I、工程 j∈J（1=転炉、S=連鋳、他=二次精錬）、各工程の設備集合 M_j。予定処理時間 p_ij、実処理時間は [p_ij, p_ij + Δ_ij] で変動
- 変更できるのは各処理後の**待機時間**（工程jで最大 W_j）と開始時刻のみ。設備割当と順序 x は固定
- **最悪メイクスパン D*(x)**：変動範囲内のどの実現値でも全制約を満たして完了を保証できる最も早い時刻。min_{x∈X} D*(x) を解く
- 動的な実行戦略に依存するため、開始時刻を変数とする静的最適化として直接書けない → STNUに帰着

## 定式化の要点：SCCスケジュール → STNU
- STNU：時点＋要求リンク（上限 Y−X ≤ b、下限は逆向き）＋不確実性リンク（[a,b] の範囲で変動、Yが起きた時に値が判明）
- 各処理 (i,j) に4時点：基準開始 S、基準完了 F（=S+p）、実完了 F'（F'−F ∈ [0,Δ]：不確実性リンク）、調整後完了 T（0 ≤ T−F' ≤ W_j：待機）
- 制約を要求リンクで：輸送 τmin ≤ S_ij' − T_ij ≤ τmax／同一設備順序 T_ij ≤ S_i'j／キャスト連続 T_iS = S_i'S（連鋳の待機＝鋳造速度調整と解釈）／段取り T_iS + σ ≤ S_i'S
- 原点Zと完了上限 T_iS − Z ≤ D を加えて STNU(x, D)。**D*(x) = min{D | STNU(x,D) is DC}**、DCはDに単調なので二分探索

## 何が難しいか
1. DCを満たす条件を、x を生成する最適化問題の制約として直接書けない
2. DCを満たしても過度の余裕を含む非効率なスケジュールになりうる
3. 余裕が少ないスケジュールはDCになりにくい → メイクスパン最小化を目的にすると非DC解に探索が集中

## 工夫・アプローチ：負閉路に基づく反復解法
- **CPで x を生成 → RUL2021[6] でDC判定 → 非DCなら負閉路から「同一設備上の直後関係の集合 G」を抽出し、それらが同時に成立することを禁止する制約 Σ q_ii'j ≤ |G|−1 を追加**して再生成
- **目標値による目的関数**：最大遅延シナリオ（全処理が p+Δ）のメイクスパンは最悪メイクスパンの下界。これが目標 D_target = f − δ（f=これまでの最良）を超える量を最小化。メイクスパン最小化ではなく目標超過最小化にして、余裕の少ない非DC解への集中を抑える
- δは30から30秒ごとに10減らし下限1（段階的に厳しく）
- DCだった場合も上限を D*(x)−1 にして負閉路を取り、禁止制約を追加（さらに良い解を探す）
- 前反復の設備割当・開始時刻をCPの初期値に

## 実験設定
- 3工程（設備 3,2,3）と5工程（4,2,2,2,4）、キャスト内チャージ U(3,9)、総チャージ30〜36。処理時間 転炉U(45,55)/精錬U(30,40)/連鋳U(35,45)分、輸送[10,30]、σ=30
- 変動：全処理 Δ=5、または確率1/2で Δ~U(5,20)。最大待機 (転炉,精錬,連鋳) = (3,3,3)/(2,5,2)/(0,10,0) と (13,13,13)/(9,20,9)/(6,25,6)
- 各100問×12条件=1200実行、制限3分/問。i9-13900KS, 128GB, CP Optimizer 22.1.1
- 比較：Random（最大遅延メイクスパン最小化）、Random T（目標値、δ=1固定）、Random D（δ減少あり、禁止制約・初期値なし）

## 結果・評価
- **Random**はDC解を得られない問題例が多発（3工程・(13,13,13)で100問中99問）。目標値を使う3手法は全例でDC達成 → 「改善目標を設けた探索」自体がDC解生成に有効
- Random D は全12条件で Random T より平均最悪メイクスパン小、%Bestも10条件で上回る → δを大きい値から段階的に減らす効果
- **提案手法は全12条件で Random D より小**。%Best 82〜100%（Random D は1〜40%）

| 例：3工程 (3,3,3) | Random T | Random D | 提案 |
|---|---|---|---|
| 平均最悪メイクスパン | 678.2 | 655.1 | **628.1** |
| %Best | 3 | 4 | **99** |

- 今後：実操業データに基づく変動範囲の設定、大規模問題での計算性能

## 実務への示唆
- 「頻繫に起きる小さな遅れには**順序を変えずに時刻調整だけで吸収**し、それが必ず可能だと事前に保証する」という要件の数理的な扱い方。製鋼に限らず、時間窓・連続性制約が厳しい工程（食品、化学、半導体の搬送連携）に転用可
- STNU/DCは「余裕をどこにどれだけ置くか」を実行戦略込みで検証できる道具。ロバスト最適化と違い、保証が「全実現値に対して」で、しかも判定が多項式（RUL2021）
- **判定器の反例（負閉路）を制約に変換して生成器にフィードバックする**ループは、CP/MILP＋検証器の組合せとして汎用パターン（lazy constraint / CEGIS的）
- メイクスパン直接最小化ではなく「目標超過の最小化」に変える、という探索の誘導の仕方

## 気になる点・[要確認]
- 変動範囲 [p, p+Δ] と最大待機 W_j は人工設定。実データの分布は今後
- 総チャージ30〜36と小規模。負閉路→禁止制約の追加数が大規模でどう増えるかは未報告
- 待機は「処理完了後」のみで、開始前の意図的な遅延（早すぎる到着）の扱いは輸送時間下限τminで間接的に表現
- 連鋳の待機＝鋳造速度調整という解釈の現実的な上限（W_S）の根拠
