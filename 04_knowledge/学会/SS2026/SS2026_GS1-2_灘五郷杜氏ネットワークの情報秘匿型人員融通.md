# 分散制約最適化による灘五郷杜氏ネットワークの情報秘匿型人員融通モデル

> [!abstract] 一言で
> 灘五郷26蔵が「秘伝の工程期間・生産計画・職人スキル評価」を互いに一切開示せず、地域全体で熟練職人を融通する問題（PP-TFSP）を定式化。
> 中央にデータを集めるMILPの代わりに**完全分散アルゴリズム DPOP** を使い、情報開示率0%で中央集権Gurobiの厳密解と100%一致。制約グラフが疎（木幅≤2）なのでDPOPの弱点（メッセージ指数爆発）が出ず最大0.5MB。

## 背景・動機
- 清酒醸造は杜氏の暗黙知に依存、高齢化・後継者不足で「技術の属人化リスク」。地域の杜氏組合・互助ネットワークが伝統的に機能
- 灘五郷：狭い湾岸に酒蔵が密集、日・週単位の人員融通が物理的に容易。四季醸造の大手蔵と冬季限定伝統製法の中小蔵が混在し職能の異質性が高い
- 「一麹、二酛、三造り」：麹→酒母→醪が24時間体制で連動、工程間に厳密な先行関係と**時間的連続性**（待機不可）。欠員やズレは品質に致命的
- 中央集権MILPが実務上不可能な理由：各蔵は市場競争下にあり、レシピ（工程目標期間）・生産計画・人事スキル評価を中央調整役や他蔵に出さない

## 問題設定：PP-TFSP
- 酒蔵 A（n=26）がエージェント、職人 W（m）、各蔵は自蔵所属職人 W_i を管理。タイムスロット T（1スロット12h、40スロット=20日）
- 各蔵 i は醸造ステージ J_i = {麹, 酛, 造り}、処理期間 p_ij
- 決定変数：S_ij（ステージ開始時刻）／x^t_{wij}（スロットtで職人wを蔵iステージjに割当）／y^t_{wik}（t→t+1で蔵i→kへ移動）／z^t_{ww'ij}（同時割当＝流派シナジー発生の線形化補助）
- **プライバシー制約**：各蔵のローカル情報 Ω_i = {W_i, J_i, p_ij, スキルベクトル s_w, 要求閾値 R_ij} は他蔵・第三者へ非開示

## 定式化の要点
1. 非中断ステージ遷移：S_{i,j} + p_{i,j} = S_{i,j+1}（待機ゼロ）。割当 x はステージ活性期間内のみ1 → 計画長 T をBig-Mに使った線形不等式
2. 異質スキル充足：d=5次元スキルベクトル、活性フラグ a^t_ij を導入し Σ_w s^h_w x^t_wij ≥ R^h_ij a^t_ij。x ≤ a でLP緩和を締める
3. 職人は同一スロットに1蔵1ステージのみ
4. 時空間移動：dist(i,k) > Δ の蔵間で連続割当禁止、y と x を結ぶ不等式
5. 目的：max Σ f_ij − α Σ dist·y。f_ij = β1·（流派一致 δ_ww'·z）− β2·（要求超過スキル＝過剰品質ペナルティ）。積 x·x' は z ≤ x, z ≤ x', z ≥ x+x'−1 で線形化

## 何が難しいか
1. **価格情報すら漏らせない**：Benders・列生成・ラグランジュ緩和・ADMM等の分散分解法は乗数・シャドウプライスを反復開示する。それ自体が「その時期どれだけ人が欲しいか（逼迫度）」「限界代替費用」を他蔵に類推させる → 反復的な価格調整プロトコルすら排除する必要
2. 一般にDPOPはメッセージサイズが変数数に指数的（木幅に依存）
3. 資源逼迫時、局所貪欲は囲い込みのデッドロック、近似DCOP（Max-Sum）はメッセージ非収束（振動）

## 工夫・アプローチ：DPOP 3フェーズ
- **第1フェーズ 擬似木構造化**：蔵間の二項制約グラフ G にDFSをかけ、親子・祖先子孫（バックエッジ）関係に構造化
- **第2フェーズ UTIL伝播（ボトムアップ）**：各蔵は子からのUTILを統合し、自身のローカル変数 X_i を max で射影消去した多次元ユーティリティ配列を親へ送る。メッセージは祖先変数のコンテキストにのみ依存
- **第3フェーズ VALUE伝播（トップダウン）**：ルートが最適割当を確定し、確定値を葉へ通知。各蔵は祖先の確定値を見て自身の最適割当を決定論的に導出
- **定理1（完全秘匿）**：通信はUTILとVALUEの2種のみ。UTILは max 射影（多対一の非可逆写像）なので受信側から制約・パラメータ Ω_i を逆算不能。VALUEは確定した共通変数（移動・割当）の値のみ → 開示率は理論的に0%
- 反復なし・一度の往復で厳密最適 → 漏洩の隙を理論的に排除
- **ドメイン知識でグラフを疎にする**：系列関係・災害時の相互扶助実績・同一杜氏組合の派遣ルートを反映して制約グラフを構築 → 木幅 w*≤2

## 実験設定
- 灘五郷（西郷・御影郷・魚崎郷・西宮郷・今津郷）26蔵の実座標、四季醸造30%/伝統70%
- シナリオ：(1)通常融通 m=160 (2)限界逼迫 m=50（過負荷率1.3）
- 比較：中央集権MILP（Gurobi、情報を全集約）、近似DCOP（Max-Sum）、局所貪欲（各蔵が囲い込み）

## 結果・評価
| シナリオ | 手法 | 最適化効率 | タスク充足率 | 開示率 | 最大メッセージ |
|---|---|---|---|---|---|
| 通常 m=160 | 中央MILP | 100% | 100% | 100% | — |
| | Max-Sum | 94.2% | 96.5% | 0% | 0.02MB |
| | 貪欲 | 97.0% | 100% | 0% | 0.01MB |
| | **提案(DPOP)** | **100%** | **100%** | **0%** | 0.50MB |
| 逼迫 m=50 | 中央MILP | 100% | 28.6% | 100% | — |
| | Max-Sum | 48.0% | 21.3% | 0% | 0.02MB |
| | 貪欲 | 25.0% | 29.8% | 0% | 0.01MB |
| | **提案(DPOP)** | **100%** | **28.6%** | **0%** | 0.50MB |

- 逼迫下で貪欲はデッドロック（効率25%）、Max-Sumは振動して実用不可。提案法は中央MILPと完全一致
- 通信回数はエージェント数に線形（50回）で確定終了
- 今後：実運用データでの長期検証、体調不良・天候による進捗ズレへの動的対応、オンデマンド交通・過疎地医療介護など他ドメイン

## 実務への示唆
- **企業間・部門間で「データを出さずに全体最適」**を求められたときの選択肢。ラグランジュ分解等は「価格情報が漏れる」という指摘は、社内でも部門間の駆け引きがある場面に効く論点
- DPOPは制約グラフの木幅が小さい時だけ実用的。「既存の信頼関係・取引関係でグラフを疎に切る」というドメイン知識の使い方が転用可能
- 非中断工程（S_j + p_j = S_{j+1}）、多次元スキル閾値、過剰品質ペナルティ、流派シナジーなど定式化パーツは一般的なプロジェクト/人員計画に流用できる
- 中央MILPとの一致で正しさを検証する評価設計

## 先行研究との位置づけ
- DCOP: Modi et al. ADOPT (AIJ 2005)、Petcu & Faltings DPOP (IJCAI 2005)
- チーム編成問題 (Nair & Tambe 2005) を時系列スケジュールと移動制約で拡張
- 社会学的背景：丹波杜氏の技術継承（佐藤・猪股 2012）、酒造技術者の地域ネットワーク（藤本 2009）

## 気になる点・[要確認]
- 「情報開示率0%」はΩ_iの直接開示についての主張。UTIL配列の形状（祖先変数のドメイン）や解の系列からの間接推測は評価外（OS1-3と同じ限界）
- 実データではなくシミュレーション。スキル値[0,10]・シナジー・過剰品質の重みβ1,β2,αの設定値は本文に明記なし
- 木幅≤2はグラフ構築の仮定に依存。実際の融通関係がもっと密なら破綻
- 26蔵×職人×40スロットのDPOPの計算時間は未記載（メッセージサイズのみ）
