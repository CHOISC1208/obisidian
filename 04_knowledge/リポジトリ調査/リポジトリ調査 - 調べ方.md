# リポジトリ調査 - 調べ方

親: [[リポジトリ調査 MOC]]

## 探す場所

| 場所 | 使い方 |
|---|---|
| GitHub 検索 | Repositories で Most stars / Recently updated に並べ替え |
| GitHub Topics | `github.com/topics/<キーワード>` でカテゴリ全体を俯瞰 |
| Awesome リスト | `awesome-supabase` `awesome-nextjs` `awesome-erp` など人が厳選した一覧 |
| Awesome Selfhosted | 業務系OSS（ERP・在庫・勤怠）のカテゴリ別一覧 |
| Hacker News / Reddit（r/selfhosted, r/nextjs） | 実運用の声 |
| OSS Insight | 人気推移・関連リポジトリ |
| Zenn / Qiita | 日本語の比較記事 |

## GitHub 検索演算子

```text
order management stars:>500 pushed:>2026-01-01
supabase rls language:TypeScript stars:>100
topic:inventory-management
```

- `stars:>N` 人気で絞る／`pushed:>日付` 放置を避ける／`language:` 言語／`topic:` タグ（精度が高い）

## gh CLI で検索するときの注意

- 複数語をそのまま渡すと **説明文のAND一致**になり、ほぼ0件になる。`--topic=` を使うか単語を減らす
- `--topic=supabase` は関係の薄い大型リポジトリが上位を占めやすい。`rls` `multi-tenant` などを併記しても絞れないことがある

```bash
gh search repos --topic=erp --stars=">2000" --sort stars --updated=">2026-03-01"
```

## 良いリポジトリの見分け方

- 最終コミットが半年以内
- README にアーキテクチャ図・セットアップ手順がある
- `tests/` や CI 設定がある
- ライセンス明記（流用するなら必ず確認）
- 巨大なもの（ERPNext・Odoo）は全体でなく**在庫・品目の部分だけ**読む

## 読み方

1. README とフォルダ構成
2. **DBスキーマ**（`schema.sql` `migrations/` `prisma/schema.prisma`）— 設計の核心
3. 自分の課題に近い機能を1つ選んで処理を追う
4. GitHub で `.` キーを押すとブラウザ上のエディタで読める
