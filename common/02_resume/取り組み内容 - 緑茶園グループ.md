# 取り組み内容 - 緑茶園グループ

親: [[取り組み内容]]（[[common/02_resume/00 MOC|common/02_resume]]）
参照元: [[緑茶園グループ/00 MOC|緑茶園グループ（クライアントフォルダ）]]

**期間**：2026-09〜現在（フリーランス・外部DXパートナー）

## 会社概要

山形の日本茶・EC・菓子製造・青果流通グループ。株式会社緑茶園（本体、実店舗＋通信販売＋菓子製造ブランド「パティスリー ルシエル」を内包）と、100%出資の別法人格である株式会社KRK（青果パッケージ・卸売）の2社構成。ビジョン2029として売上10億円・粗利25%を掲げる。

## 全体像

ツール自体は足りているが**連携が足りていない**（受注・仕入・在庫・会計が別ツールで完結し、間を人が手作業で繋いでいる）状態を解消するのが軸。受注チャネル統合（テーマ1）とグループウェアの役割再定義（テーマ2）の2テーマに対する具体的な開発物を、最終的に1つの統合コンソールへ集約する方針で推進している。

## 案件一覧

### EC Channel Console（開発中）

複数のECモール（楽天市場・Amazon・Yahoo!ショッピング・au PAYマーケット・Shopify・Temu・LINEギフト）の受注データを、それぞれの公式APIで取得・表示する社内向けツール。既存の一元管理システム（easyECS＋クロスモール）では対応できない「断絶チャネル」を補う位置づけ。

- 実装スタック：Next.js 16（App Router）／React 19／TypeScript／Tailwind CSS v4／fast-xml-parser（Yahoo・au PAYのXML応答対応）
- 進捗：7チャネル中5チャネルでAPI実装済み（楽天：RMS WEB SERVICE、Amazon：SP-API Orders v0、Yahoo：注文検索/詳細API、au PAY：Wow!manager API、Shopify：Admin GraphQL API）。**au PAYは本番デプロイでの疎通・実データ取得まで確認済み**。残るTemu・LINEギフトは認証情報フォームまで実装し、受注取得はAPI仕様待ち
- 先方の現状運用（Amazon・Yahoo・au PAYはPower Automateで自動化、Shopify・Temu・LINEギフト・電話/カタログは完全手動、ふるさと納税はeasyECS未連携で別管理）を確認し、「表示ツール」から「easyECSへの変換器」へ役割を広げる構想を整理中

### Airtable「入荷記録表」再構築（要件定義・POC実装済み）

農産物の入出庫を管理していたAirtable運用を、自前スクラッチ（Vercel／Supabase／Next.js）で再構築する案件。kintone案（本体ライセンス契約済み・帳票プラグイン買い切り20万円）との比較検討を重ね、13テーブル・約90カラムの設計まで具体化した上で、統合コンソールの仕入機能として自前で作る方針を確定。価格計算ロジック・データ構造はスクリプト内容まで解明し、過去の削除事故を防ぐための`ON DELETE RESTRICT`設計や9列の複合ユニーク制約など、実装レベルの要件を詰めている。

### 統合コンソール（`ryokuchaen-platform`、設計中）

上記2つのリポジトリ（EC Channel Console＝受注取得、Airtable再構築＝仕入）を1つの統合コンソールへまとめる設計・調査。着手前にSupabaseプロジェクトの同一性、認証基盤、Next.js/React/Tailwindスタックの共通性を確認した上で、統合の障害（データアクセス層が2系統に分かれている、マイグレーション履歴の不整合、権限モデルが存在しない、商品コードの偶然の文字列一致など）を重大度つきで洗い出した。データアクセス層の統一方針、SQLマイグレーションの管理ルール、ロール単位＋個人単位の権限モデル（4ロール）を設計し、段階1（雛形・デザイントークン・DB骨組み・ログイン・App Shell）を実装済み。

## 使ったスキル・技術

Next.js／React／TypeScript／Tailwind CSS v4（複数リポジトリ共通スタック）／Supabase（Auth・Postgres、スキーマ分離による複数アプリ共存設計）／外部ECモールAPI連携（RMS WEB SERVICE・SP-API・Yahoo注文API・Wow!manager API・Shopify Admin GraphQL API）／XMLパース（fast-xml-parser）／複数リポジトリの統合設計（権限モデル・マイグレーション管理・データアクセス層の統一）
