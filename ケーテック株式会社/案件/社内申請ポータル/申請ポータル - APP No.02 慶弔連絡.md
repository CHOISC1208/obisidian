## これは何か

結婚・出産・弔事・傷病等の慶弔連絡を電子化し、総務人事・経理への連携を自動化する。
**プライバシー配慮が最重要**のAPPで、唯一「総務人事グループのみ閲覧可」の権限設計を持つ。

### 規程を読んで判明した「元Excelの要件が間違っていた」件

元Excelには **「条件分岐2つ（金額・休暇日数）」** と書かれていた。しかし規程には
**特別休暇の定めが無かった**。

→ `SpecialLeaveDays`（特別休暇日数）列を**削除**した。当初の要件の半分は存在しない要件だった。

## 慶弔マスタ（`KeichoMaster`）の構造

```
制度種別 × 対象者 × 雇用区分 × 同居条件（祖父母のみ） × 傷病条件（傷病見舞金のみ） → 金額
```

| 列 | 選択肢 |
|---|---|
| `RequestType` | 結婚祝金 / 出産祝金 / 弔慰金 / 傷病見舞金 |
| `TargetPerson` | 本人 / 配偶者 / 子女 / 父母 / 祖父母 / 兄弟姉妹 |
| `EmploymentTier` | 区分A/B（正社員・嘱託員／勤続3年以上のパート・契約社員）／ 区分C（勤続3年未満のパート・契約社員） |
| `CohabitingCondition` | 該当なし / 同居 / 別居 |
| `InjuryCondition` | 該当なし / 業務上 / 業務上以外 |
| `Amount` | 慶弔金額 |

**特別加算金・社葬等協議事項は定額表が存在しないため行を持たない。**

このマスタは SPFx の「マスタ管理」画面から総務人事が直接編集する運用
（規程改定時の反映責任者を決める必要がある）。

## 規程から導いた設計判断

| # | 決定 |
|---|---|
| 1 | 勤続年数の起算・カウントは**自動計算せず自己申告**（従業員マスタが無いため） |
| 2 | 「入社後2回目以降」も自己申告のチェック。復縁時の扱い（支給対象外）は SPFx で判定せず運用に委ねる |
| 3 | 「実祖父母 同居/別居」も自己申告。承認者が必要と判断した場合のみ追加確認 |
| 4 | 社葬・葬祭料等（規程第6条2項・都度審議）は「社葬等協議事項」として**起票のみ**。金額決定はフロー外 |
| 5 | 特別加算金は**人事側が起票**（本人からの申請フローではない） |
| 6 | 慰労金（定年退職者への品物・花束の現物支給）は**本ポータルのスコープ外** |
| 7 | 承認段階は**第一段階のみ**。金額の大小によらず第二段階承認は設けない |
