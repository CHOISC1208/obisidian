# APP No.01 仮払金申請

| リスト内部名 | `AdvancePayments` |
| 表示名 | 仮払金申請 |

| 要望部署 | 経営SPG ／ 元重要度: 低 |
| 承認段数 | 1段（条件分岐なし） |
| 状態 | ✅ リスト・フォーム構築済み ／ ❌ フロー未実装 |

## これは何か

出張仮払・経費の仮払金申請を電子化する。**最もシンプルなAPP**で、
[[申請ポータル - APP No.07 年休申請]] の雛形をそのまま横展開した最初の1本。

狙い（元資料より）: 経理担当者の事務負担軽減、処理漏れ防止、MF（マネーフォワード想定）への入力簡素化。

## 列（固有列のみ）

| 内部名 | 表示名 | 型 | 備考 |
|---|---|---|---|
| `Title` | 件名 | Text（必須） | 申請者が自由入力（**自動生成しない**） |
| `ExpenseCategory` | 区分 | Choice | 出張 / 経費。**金額より前に配置**（2026-08-17 追加） |
| `Amount` | 仮払金額 | Currency | 数字のみ入力可 |
| `Purpose` | 用途・目的 | Note | |
| `PaymentDueDate` | 支払希望日 | DateTime(DateOnly) | |
| `SettlementDueDate` | 精算予定日 | DateTime(DateOnly) | 任意 |

`Status` は共通列を使い、このAPPだけ「**精算済**」の値を使う。

## 依頼と対応の履歴

| 日付 | 先方の回答 | 判断 | こちらの対応 |
|---|---|---|---|
| 2026-08-17 | 対象範囲は出張・経費の**両方** | ✅ | `ExpenseCategory`（出張/経費）列を追加。申請時にまず選ばせるため金額より前に配置 |
| 2026-08-17 | 金額による条件分岐は**無し** | ✅ | 承認者の切り替え等の分岐を作らない判断を確定 |
| 2026-08-17 | 経理への通知は**経理グループ**宛 | ⏸ | フロー側の通知先設定として記録。フロー本体は未着手 |
| 2026-08-17 | **精算完了まで管理対象**とする | ✅ | 既存の `Status=精算済` と `SettlementDueDate` 列で対応可能と判断し、**スキーマ変更なし**で済ませた |

> [!tip] スキーマを変えずに済んだ例
> 「精算まで管理する」という要件に対し、**すでに設計に入っていた** `Status` の「精算済」と
> `SettlementDueDate` でそのまま対応できた。要件を先読みして列を持っていた分が効いた数少ない例。

## フローに期待する動き（未実装）

1. 項目作成トリガー → `Applicant` / `ApplicantDepartment` / `Status=申請中` を設定
2. `Approver`（申請者が選択した所属長）へ「承認の開始と待機」
3. 承認 → `Status=承認済` ＋ **経理グループへ通知**（申請者・部署・金額・用途・支払希望日・リンク）
4. 却下 → `Status=却下` ＋ 申請者へ通知（承認者コメント付き）
5. 精算完了後、担当が `Status=精算済` に更新（手動運用の想定）

## スコープ外

- **MF（マネーフォワード）への自動入力** — API連携は対象外。Lists → Excel エクスポートで入力を簡素化する
- 精算処理そのもののワークフロー化（将来拡張）
