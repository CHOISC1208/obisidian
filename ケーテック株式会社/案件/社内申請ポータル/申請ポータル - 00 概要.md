## これは何か

M365 の標準機能だけで組んだ社内申請の受け皿。1つの SharePoint Online サイトに、
申請種別ごとの Microsoft Lists と、それらを横断する SPFx 製の申請ポータル画面を置いている。

- **入力**: SPFx 申請ポータル（Lists 標準フォームの代替）
- **保管**: Microsoft Lists（そのまま申請台帳になる）
- **承認**: Power Automate「承認の開始と待機」を APP ごとに1本（**未実装**）
- **提供**: PnP PowerShell によるテンプレート適用（IaC）

### 絶対に守っている技術制約

| 制約 | 理由 |
|---|---|
| Forms 不使用 | — |
| プレミアムコネクタ不使用 | **追加ライセンス費用を発生させない**（先方テナントが標準ライセンスのまま動くこと）が本プロジェクト最大の狙い |
| Dataverse をテーブルとして使わない | 同上 |
| **例外**: Power Automate の環境変数 | 既定環境の Dataverse を使うが、フロー内から参照する分にはプレミアム不要（2026-08-10 に公式ドキュメントで確認）。フロー設定値のハードコード回避に使う |
| リポジトリが正、テナントは適用結果 | テナントを直接いじって済ませない。直した場合は `export-template.ps1` で吸い出して fragment に戻す |
| 列の内部名は英語 PascalCase | 表示名のみ日本語 |
| 物理削除禁止・論理削除（`Status`）で管理 | 改ざん耐性 |

> [!warning] 「構築済み」の意味に注意
> 上表の ✅ は**リストとフォームができている**という意味で、申請業務が回っている状態ではない。
> フローが動いていないため、以下はすべて空 or 初期値のまま動かない。
>
> - `Status`（申請中のまま変わらない）
> - `Applicant`（申請者）・`ApplicantDepartment`（所属部署）
> - `ApprovedAt` / `ApproverComment`
> - 慶弔の `PlannedAmount`（支給予定額）、昼食の `Amount`（金額）
> - 承認通知・経理通知・締切通知のすべて
> - 昼食の「期間まとめ申込」を1日単位へ展開する処理
>
> 先方への説明時にここを混同しないこと。→ [[05 要確認事項]] V-4
