# 企画と設計のポイント（調査）

親: [[05_game/00 MOC|05_game]]

初心者が1本目のゲームを作る前に押さえる企画・設計の要点。**Web検索のスニペットベースの一次調査**で、各ページの本文までは読んでいない。テンプレの根拠として使い、採用するときは出典で裏を取る。

## 1. 企画書は1ページに収める

- 1ページに収まらないなら、スコープが大きすぎるサインとして使える。
- 試作ができる前に1ページを超えたら、計画しすぎ。
- 書く項目は絞る：ピッチ（一行コンセプト）、コアループ、機能、進行、アート・音、**やらないことリスト**。
- 企画書は契約ではなく道具。ゲームの実態とずれた企画書は、無いより悪い。試遊で分かったことを反映して更新する。
- 参考：Stone Librande の GDC 講演（1枚の注釈つき図で設計を示す方式）。

→ テンプレの `一枚企画` `スコープ` にそのまま反映済み。

## 2. コアループを最初に決める

- 動詞3〜4個で書く（例：避ける→集める→強化する）。
- 目安は30秒程度の1周：行動 → フィードバック → 報酬 → もう一回。
- 企画書の中心。ここが面白くなければ他を足しても面白くならない。

→ `面白ポイントとコアループ` に反映済み。

## 3. 完成しない原因と対策（個人開発）

主な原因は **機能の肥大化**。小さな追加を重ねるうちにコアループが埋もれ、燃え尽きて放棄する。

| 対策 | やること |
|---|---|
| MVPを定義する | 核の体験を1つ決め、それを検証できる最小の要素だけ作る |
| 優先度を付ける | Must / Should / Could / Won't(今回は) に分類し、Must以外は初版に入れない |
| タイムボックス | 機能ごとに時間を決め、超えたら次へ。何度も超えるなら見積もりが非現実的 |
| 早く遊んでもらう | 試作の段階で他人に触ってもらう |
| 見積もりは2倍 | 予定時間を少なくとも2倍で見る（1記事の主張。目安として） |

→ `スコープ` に「作らない」欄あり。優先度の4分類を使うならそこへ追記する。

## 4. Unity × Git の初期設定

- Edit > Project Settings > Editor：**Version Control = Visible Meta Files**、**Asset Serialization = Force Text**（新しいバージョンでは既定の場合がある。必ず確認する）。
- `.gitignore`：`Library` `Temp` `Obj` `Build` などの生成物を除外。**`.meta` は絶対に除外しない**。
- Git LFS：**フォルダ単位ではなく拡張子単位**で指定（フォルダ指定だとテキストの `.meta` までLFS対象になる）。画像・音声・動画・FBX など。`.asset` はTerrainなど別物が混ざるので注意。
- 任意：UnityYAMLMerge を設定すると、シーン・プレハブの衝突を解消しやすい（ソロ開発では優先度低）。

→ `技術構成` に反映する。

## 次に調べる候補

- 試作（グレーボックス）の進め方と、面白さの確かめ方（プレイテストの聞き方）
- 作りたいジャンルの類似ゲーム分析
- プラットフォーム別の公開費用・審査（変わりやすいので公式で確認）
- AI生成素材の商用利用条件（サービスごとの最新規約）
