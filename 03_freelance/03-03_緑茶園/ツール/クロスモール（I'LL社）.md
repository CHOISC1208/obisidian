# クロスモール（I'LL社）

親: [[00 MOC|緑茶園グループ MOC]] ／ 関連: [[04 ツールリファレンス]] ／ [[テーマ1 - 受注チャネル統合とツール複数人化]]

> [!info] このノートの位置づけ
> 緑茶園グループが**在庫連動・商品ページ作成**の用途で稼働させている、株式会社I'LL のEC一元管理パッケージ。ベンダーが公開している初期設定資料（チャネルごとに1本、Ver.と最終更新日つき）を読み解いた**一次情報の書き起こし**。[[EC Channel Console - 00 概要]] の設計判断の根拠になっているため、資料そのものではなくここを参照する。
>
> **出典**：I'LL社 初期設定資料 — Yahoo!ショッピング Ver.3.29.30（2026-08-06）／Amazon Ver.1.10.11（2026-08-03）／Shopify Ver.1.31.32（2026-05-26）／au PAY マーケット Ver.1.14.15（2025-03-31）／LINEギフト 連携資料 Ver.1.15.16（2025-11-11）。2026-09-07 に取得。

## 対応チャネルと受注の取得方式

| チャネル | 注文受信 | 在庫送信 | 出品 |
|---|---|---|---|
| 楽天市場 | API | － | － |
| Amazon | **注文レポートの定期ダウンロード** | API | API |
| Yahoo!ショッピング | API | API／FTP（選択可） | 連携不可 |
| au PAYマーケット | API | FTP | FTP |
| [[Shopify]] | **注文確認メールのパース** | FTP | 連携不可 |
| LINEギフト | API | API | 連携不可 |

> [!important] 一元管理パッケージだからAPI直、とは限らない
> Shopifyは**注文確認メールを取り込む**方式、Amazonは**注文レポートを定期ダウンロード**する方式。[[EC Channel Console - 00 概要]] はどちらも公式APIを直接呼んでおり、**受注取得の方式としてはEC Channel Consoleのほうが直接的**。ただしクロスモールは在庫送信・出品・画像アップ・配送便変換まで担うため、業務カバー範囲では比較にならない。

資料に明記されている運用上の副作用は次の2つ。

- **Shopify**：クロスモール専用のメールアカウントを用意する必要がある。クロスモールは取込後にメールサーバから全メールを削除するため、他のメーラーで先に受信すると取り込めなくなる。フリーメールは非推奨。
- **Amazon**：クロスモールが一定間隔で注文レポートをダウンロードするため、店舗側が「1日1度、自分で注文レポートをダウンロードする」といった**既存の運用が行えなくなる**。

## au PAYマーケット：接続元IPアドレスの登録

au PAYマーケットのAPIは、Wow!managerに登録した送信元グローバルIPからのリクエストしか受け付けない（クロスモールが扱う6チャネルで唯一）。資料では店舗側に**14個のIPアドレス**を登録させている。

```
121.83.254.71    121.83.254.72    121.83.254.109   121.83.254.110
121.83.254.125   121.83.254.126   121.83.254.127   121.83.254.164
121.83.254.165   113.37.111.122   122.215.113.202  124.35.44.218
122.218.59.88    13.112.7.206
```

`121.83.254.*` は自社データセンター帯、`13.112.7.206` はAWS東京。**一元管理SaaSは、この種のAPIに繋ぐために自前で固定IPを確保している**というのが実態で、「クラウドサービスだから送信元IPは動的」という話ではない。ロジレスも同様に4個を公開している。

→ この事実は [[EC Channel Console - 00 概要]] の「au PAYマーケットのIP制限」の判断根拠。月数百円のVPS1台で同じ構造は作れる。

## LINEギフト連携の仕様（EC Channel Console 実装時の前提）

クロスモールはLINEギフトを**APIで**連携している。認証はショップCMSの「アプリ > 新規登録」で発行する OAuth2 の認証情報。審査は無く即時発行。

チャネル特有の制約が資料に列挙されており、実装するなら設計に効く。

| 制約 | 内容 |
|---|---|
| **注文者情報が取得できない** | 氏名もメールアドレスも来ない。取れるのはお届け先情報だけ。注文者へのメール送信はショップCMS上で行う必要がある |
| ポイント・売上金 | 値引き額が金額に反映されない（差し引かれていない額が返る）。LINEギフト側でも確認できない金額のため |
| 仮注文 | 注文者が注文したあと、**お届け先が住所を確定するまで**は仮注文。確定後に本注文になる。バリエーション変更・期間経過・店舗キャンセルでキャンセルとして残る |
| 取込対象ステータス | 「発送待ち」または「取込完了」。全体の遷移は 支払待ち → メッセージ送信待ち → 住所入力待ち → 発送待ち → 取引完了 |
| 初回取込 | 連携開始日の17日前の注文日時から |
| SKU | クロスモール側SKUコード＝LINEギフト側バリエーションコードでないと連携できない。LINEギフトは**売れた実績のある商品のコードを変更できない** |

## 緑茶園グループでの使われ方

[[04 ツールリファレンス]] では「在庫連動・商品ページ」の用途で🟩稼働。受注一元管理は [[03 業務フローとツール状況|easyECS（SAVAWAY）]] が担っており、**クロスモールの受注連携メニューは使われていない**と読める。

> [!warning] 前提が食い違っている可能性（2026-09-07、未確定）
> 棚卸では Temu・LINEギフト・[[Shopify]] を「一元管理に取り込めない🟥断絶」として扱ってきた。しかし**クロスモールはLINEギフトとShopifyの両方に受注連携メニューを持っている**。つまり手作業になっている理由は「ツールが対応していないから」ではなく、「その用途で契約・設定していないから」である可能性がある。
>
> ただし次が未確認のため、**断絶の判断は現時点では変更しない**。
> - 緑茶園のクロスモール契約に、これらのチャネルの受注連携が含まれているか（店舗数課金・オプション費用の有無）
> - 受注一元管理を easyECS からクロスモールへ寄せることが、[[06 触らない領域]]（easyECS＋クロスモールには手を入れない）と矛盾しないか
> - Temuについては資料が見つかっておらず、クロスモールが対応しているかどうか自体が不明
>
> → [[08 要確認事項]] に質問として起票。確定するまでこの領域の扱いは暫定。
