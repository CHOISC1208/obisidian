# リリースノート｜2026-10-28（v1.42.0〜v1.43.0）

親: [[platform - 00 概要]] ／ 関連: [[テーマ5 - 問い合わせ情報のナレッジ化]]・[[株式会社KRK]]

> [!info] このノートの位置づけ
> 利用者に見える変更と、その判断の背景だけを書く。構成・DB 設計の実体はリポジトリ（`sql/`・`docs/`）が正本。PR：ryokuchaen/ryokuchaen-platform#21

## 1. 請求書（入荷・出荷 → 請求書取り込み）：突合をやめ、「照合」タブに

- **やめたこと**：請求書の明細を入荷データと突き合わせる機能。要らなくなった（2026-10-28 の指示）
- **できたこと**：請求書の画面に「明細／照合」のタブ。照合タブは**集荷日ごとの合計数**を出し、人が数えた合計数を手入力すると **OK／NG** を表示する
- 合計数には**資材（ダンボール）を含めない**（数える単位が違うため）
- 手入力の値は DB に保存しない（ブラウザに控えるだけ）。残したくなったら別途テーブルを足す

## 2. ダッシュボード：KRK受注残を先頭に、要注意モールのチップ

- **KRK受注残をサイドバーの先頭**に移した（先方が一番大事にしている画面）
- **「要注意モール」マスタ**を新設（マスタ → 受注連携）。EC名・表示ロゴ・easyECS のモール区分・表示順・有効／無効を登録する。最初は **Amazon（モール区分 `05`）** のみ
- 該当モールの注文を含む SKU にはロゴ、発送予定日の見出しにはそのモールの**注文件数**を出す（まだ作る SKU の分だけ数える）
- モールが増えたらマスタに足すだけで同じ表示になる
- 権限は `ec.watch_malls.edit`（どのロールにも未付与。権限設定で付ける）

## 3. CS：RMS 貼り付けをやめ、「注文を探す → プロンプト生成 → 回答の記録」に

> [!warning] 方針の変更
> [[テーマ5 - 問い合わせ情報のナレッジ化]] で前提にしていた「**過去の問い合わせ・店舗の返信を貯めて検索する（RMS のメッセージ画面の貼り付け、過去データの取り込み）**」は、2026-10-28 に**やめた**。既に入っていた 213 件も不要として削除した。代わりに、問い合わせごとに LLM 用プロンプトを作り、**LLM の回答と、人が直した最終回答を並べて残す**方式にした。

- **流れ**：①問い合わせを登録 ②チャネル（7モールから選択）と注文番号を入れて「探す」 ③お客様の発言を入れて「プロンプトを生成」（ポップアップでコピー） ④LLM の回答を貼る ⑤人が直した最終回答を貼る
- **注文を探す**：押すたびに最新を取ってくる。KRK受注残と同じ easyECS の最新スナップショットを、モール側の注文番号か easyECS の受注番号で引く。受注残に無ければ出荷済みの履歴も探す
- **プロンプトの文面はマスタで管理**（マスタ → CSプロンプト）。注文情報・これまでのやり取り・お客様の発言は自動で入り、それ以外（役割・対応方針・文体・出力形式）をマスタで直す。**対応方針は仮の文面なので、社内の基準に書き換える必要がある**
- **最終回答を LLM の回答と比べて、プロンプトを直していく**ための記録。生成時のプロンプト全文は残すので、あとでマスタを直しても当時の文面が分かる
- **1 回で終わらない問い合わせ**：1 件の問い合わせに複数のやり取りを持たせ、丸と縦線でつないで表示する（丸を押すと折りたためる）。2 回目以降のプロンプトには、前のやり取りが入る
- 権限は `ec.inquiries.view`／`ec.inquiries.edit` に加えて、プロンプトのマスタ用に `ec.cs_prompts.edit`（未付与）

> [!warning] 未確定・要確認
> - **Shopify・Temu は easyECS に連携されていない**ため、注文を自動では取れない（画面にもその旨を出す）。取りたい場合は各チャネルの API で個別に引く必要がある。→ 先方の「easyECS への不満」の件として扱ってよいか、先方に確認する
> - プロンプトの対応方針に入れる**社内の対応基準・クレーム方針**は先方から受領待ち
