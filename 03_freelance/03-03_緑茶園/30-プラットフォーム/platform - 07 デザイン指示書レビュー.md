## 結論

> [!success] 方向性は既存アプリの延長線上にあり、無理なく移せる
> 既存の2アプリはすでに「淡い地色・1pxの区切り線・影をほぼ使わない・演出なし」で作られている（`--color-canvas: #f6f7f9`、`--color-line: #e3e6ea`）。指示書はこの骨格を保ったまま、**グレーを深緑と陶器グレーに置き換える**方向なので、画面の構造を作り直す必要はない。

> [!warning] 実装前に直す点（4つ）
> 1. **CSS変数の HSL が HEX と一致していない。** 特に「成功」は明度が5ポイントずれ、別の色になる（→ 1章）
> 2. **CSS変数が Tailwind CSS v3 時代の書き方。** 統合先の Tailwind v4 にそのまま貼ると色として効かない（→ 1章）
> 3. **コントラスト不足が4か所。** 警告の文字（2.89）、成功バッジの文字（4.47）、アクセント色での選択中表示（2.78）、入力欄の枠（1.23）（→ 2章）
> 4. **ヘッダーのモジュールタブ（受注／入出荷／帳票／マスタ）と、05 の業務別の構成（仕入／EC）が食い違う。** 帳票とマスタは仕入と EC の両方にまたがる（→ 3章）

## 1. CSS変数の検算

指示書6章の HSL を HEX に戻した値と、指示書の HEX から逆算した HSL を並べた。

| 役割 | 指示書の HEX | 指示書の HSL | その HSL を HEX に戻すと | HEX から逆算した HSL |
|---|---|---|---|---|
| background | `#F2F3EF` | `90 12% 94%` | `#F0F2EE` | `75 14% 95%` |
| foreground | `#1F2A22` | `130 15% 15%` | `#212C22` | `136 15% 14%` |
| primary | `#2F5233` | `129 27% 26%` | `#305436` | `127 27% 25%` |
| secondary / border / input | `#D8DED2` | `96 15% 85%` | `#D8DED3` | `90 15% 85%` |
| muted | `#E8EAE3` | `90 12% 90%` | `#E6E9E2` | `77 14% 90%` |
| muted-foreground | `#5B6358` | `105 6% 37%` | `#5C6459` | `104 6% 37%` |
| accent | `#7A9B76` | `108 15% 55%` | `#829D7B` | `114 16% 54%` |
| destructive | `#9C4A3C` | `9 41% 42%` | `#974C3F` | `9 44% 42%` |
| ring | `#3B5D42` | `130 26% 29%` | `#375D3D` | `132 22% 30%` |
| warning | `#B8863B` | `38 51% 47%` | `#B5883B` | `36 51% 48%` |
| **success** | **`#4C7A52`** | **`128 25% 34%`** | **`#416C47`** | **`128 23% 39%`** |

- 大半は見分けがつかない程度のずれだが、**success は明度が 39% → 34% と暗くなり、プライマリ（`#2F5233`）との差が縮む**。指示書の「プライマリより少し明るい緑」という意図から外れる
- HSL を整数に丸める以上、HEX に戻すと1程度ずれるのは避けられない
- **推奨：HEX を正本にし、変換を挟まない。** Tailwind v4 では CSS 変数に HEX をそのまま書ける

### Tailwind v4 での書き方の違い

- 指示書の `--primary: 129 27% 26%` は「色の成分だけ」を入れる形式で、Tailwind v3 と当時の shadcn/ui が `hsl(var(--primary))` で包む前提の書き方
- Tailwind v4 と現行の shadcn/ui は、**変数に色そのもの**（`#2F5233` など）を入れ、`@theme inline` で Tailwind の色名（`--color-primary`）に対応づける。成分だけの値を v4 に貼ると色として解釈されず、効かない
- `--warning`・`--success` は shadcn/ui の既定に無いため、`@theme inline` にも自分で足さないと `bg-warning` などのクラスが使えない
- 角丸：v4 版の shadcn/ui は `--radius` から段階別の角丸を計算して定義する。指示書の「ボタン・入力欄 6px」はその中間段にあたる見込み（導入時に生成される CSS で確認する）
- 既存アプリの独自トークン（`--color-surface` / `--color-canvas` / `--color-line`）は廃止し、指示書のトークンに寄せる

## 3. レイアウト：モジュールタブと 05 の構成

| | デザイン指示書 | 05 統合方針 |
|---|---|---|
| 第1階層 | **ヘッダーのモジュールタブ**：受注／入出荷／帳票／マスタ | サイドバーの**業務**：仕入／EC／設定 |
| URL | 指定なし | 第1階層＝スキーマ名（`/inventory`・`/ec`） |
| サイドバー | 選択中モジュールの項目だけ・240px 固定・権限で絞る | 業務ごとのグループ・折りたたみあり |

帳票（支払明細書・将来のMDC出力）もマスタ（取引先・商品・SKU対応表・チャネル認証情報）も、**仕入と EC の両方にまたがる**。業務で切る 05 の案とモジュールで切る指示書は、そのままでは両立しない。

**推奨：画面の入口（ヘッダーのタブ・サイドバー・URL）はモジュールで切り、データの持ち主（スキーマ・`lib/`・権限キー）は業務で切る。**
05 の「URL の第1階層＝スキーマ名」はここで改める。スキーマ・`lib/`・権限キーを業務で揃える点は変えない。

## 4. shadcn/ui 導入で注意すること

- 05 では「入れない」としていたが、**指示書で導入に変わった**（05 の D9 に記録）。両アプリとも Radix などは入っていないので新規の導入になる
- 既定の Card などには**影と大きめの角丸**が付いている。指示書4章（影なし・パネル8px）に合わせて上書きし、一覧のテーブルはカードで囲まない
- ダイアログやドロップダウンには開閉のアニメーションが付く。操作への応答なので指示書5章の範囲内だが、`prefers-reduced-motion` のときに止まるかは導入時に確認する
- 既存の自前部品は shadcn/ui の部品に置き換えられる：サイドピーク（仕入 `SidePeek`）→ Sheet、取引先の絞り込み（仕入 `PartnerCombobox`）→ Command＋Popover

## 5. フォント

- Noto Sans JP を 400・500 だけ読み込む。日本語フォントは容量が大きいので、読み込み方（`next/font` のサブセット指定など）は実装時に実測して決める
- 既存の2アプリはシステムフォント（ヒラギノ・游ゴシック・メイリオ）なので置き換えになる
- 既存コードの `font-semibold`（仕入16／EC 17）と `font-bold`（EC 1）は、すべて 500 に置き換える
