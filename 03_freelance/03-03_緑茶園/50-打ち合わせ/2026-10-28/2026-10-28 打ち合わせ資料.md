## 4｜Shopify の実装が完了した

関連: [[変換器構想とMDC出力]]

easyECS に取り込めない Shopify の受注を、**MDC 形式 CSV**として出力できるようにした（2026-10-19、`main` にマージ済み）。

- 受注 > Shopify で期間を選んで一覧を取得 → 未出力の注文にチェック → 「MDC出力」で CSV（Shift_JIS・84列）をダウンロード
- 出力した注文は「出力済み」になり、二重に取り込まれない。easyECS への取り込みに失敗したら「解除」で未出力に戻せる
- Shopify 接続は Dev Dashboard アプリ（Client ID / Secret）に対応。トークンは自動更新
- 本番 DB の出力済み管理テーブルは適用済み。**まだ1件も出力していない**（実運用での確認はこれから）

| 確認すること | 先方の回答（当日記入） |

| 取り込めない項目・値のずれはないか（配達希望日は「希望なし」固定、フリガナ・ポイント・会員IDは空欄／0） | |
| Shopify の月間注文件数（運用に乗せる頻度の見当） | |
| 次に MDC 出力を入れるチャネル（LINEギフト・Temu・ふるさと納税・電話／カタログ） | |

## 5｜CS問い合わせのナレッジ蓄積（試作ができた）

関連: [[テーマ5 - 問い合わせ情報のナレッジ化]]

前回までのお話（ChatGPT に学習させている対応基準は、いつか消える／社内ナレッジは外に出したくない）を受けて、**社内に蓄積して検索できる画面**を試作した。ヘッダーのタブ「CS」→「問い合わせ」。

**入れてもらった過去データ（楽天・213件）を取り込んだ結果**

- 期間 2025/10/15〜2026/10/15。5〜6月と8〜10月に集中（さくらんぼ・桃の時期）
- 店舗の返信があるものは 210件。担当は遠藤さん・槙さんの2人
- 内容の見当（1件で複数に当たる）：**発送・納期 159件**／品質（傷・味など）65件／配送先・日時の変更 63件／キャンセル・返品 35件／のし・包装 15件／在庫・予約 13件／領収書 3件

**できること（第1段階）**

- 楽天 RMS のメッセージ画面をコピーして貼ると、日時・お客様の発言・店舗の返信・担当・注文番号に自動で分けて登録（お客様の氏名は保存しない）
- キーワード（スペース区切り）・カテゴリ・品目・期間で検索。「そのまま使える返信」に印を付けて、ナレッジとして絞り込める（入り口を狭めて取捨選択する方針）
- 修正・削除は記録が残る。見られる人は権限で絞る（お客様の発言が入るため）

**ベクトル検索（AIの検索）は、まだ入れない**：今の量（数百件）は、キーワード検索で足りる。使ってみて「探しても出てこない」が出てから決める。

| 確認すること | 先方の回答（当日記入） |
|---|---|
| 画面を触ってみてどうか（検索・貼り付け登録）。足りない項目 | |
| **返信文案の下書きにAIを使ってよいか**。使う場合は、お客様の名前を取り除き、社内のナレッジが学習に使われない契約のサービスだけにする。使わない場合は、検索と返信例の閲覧だけにする | |
| 「そのまま使える返信」を選ぶ人は誰か（遠藤さん・槙さん？） | |
| 見られる人（権限）はどの範囲か | |
| Amazon・Yahoo などの問い合わせも、同じように貼り付けて蓄積するか | |
| 発送遅延の問い合わせに「具体的な発送日」を答える仕様にする。受注残ボードの発送予定日を、そのまま答えてよいか。ずれたときはどうするか | |

**遅延連絡について**：受注残ボードで、**遅延している注文と発送予定日を特定する**ところは、実装できそう。該当のお客様への一括メールは、楽天が RMS の外から返信を自動で送りにくいため、まずは「文面と宛先の一覧を出す」形が現実的。納期ずらし（easyECS の書き換え）は、先方の意向どおり対象外。
