# Airtable代替機能の説明・過不足確認（2026-09-28）

> [!info] このノートについて
> 2026-09-28打ち合わせ、項目6の詳細。inventory側（Airtableからの移植・段階3で完了）の各画面を説明し、Airtable運用と比べて過不足がないかを確認する。

## 説明する画面

| モジュール | 画面 | 内容 |
|---|---|---|
| 入出荷 | 入荷入力 | 取引先と取引日を選ぶと、その取引先の商品が前回の仕入とともに並ぶ。数量を打つだけで伝票になる |
| 入出荷 | 取引一覧 | 行を選んで、または絞り込み結果すべての支払い進捗をまとめて変更できる。支払明細書を発行済みの行は、明細書を取り消すまで修正できない |
| 入出荷 | 月締め | 締め日（月末）までの清算指示待ちの明細を、取引先ごとに支払明細書にまとめる。KRKはKRKからの請求書で精算するため出していない |
| 帳票 | 支払明細書 | 発行済み明細書の一覧（新しい順に300件まで）。発行自体は「月締め」から行う |
| 帳票 | 取引のCSV出力 | 条件を選んで取引一覧をCSVで書き出す（全件対象） |
| マスタ | 取引先 | 取引先の登録・編集 |
| マスタ | 商品・原価 | 商品・規格の編集、原価の変更（今日時点で有効なもの） |
| マスタ | 規格マスタ | 規格の名前・並び順の編集 |
| マスタ（POC期間のみ） | データ品質 | Airtableから抽出したときに見つかった未解決の問題の一覧 |

## 確認したいこと

- Airtableでの運用と比べて、**足りない機能・画面がないか**
- 現状把握できている論点：
  - 顧客マスタ・請求書・納品書は「後回し」と決定済み（第1弾は仕入側で完結）→ [[Airtable再構築 - 00 概要]]
  - インボイス要件／DocsAutomator継続可否がまだヒアリングで潰しきれていない → [[Airtable再構築 - 00 概要]]「次のアクション」
  - 支払明細書（＝月締め入荷記録）が現行業務の中核アウトプットという整理は反映済み
