## 4｜easyECSへの受注データ集約：優先順位とスケジュール

### 今回の要望

**新しく追加したダッシュボード（経営サマリー・商品・モール・季節・分析・商品ポートフォリオ・商品カルテ）は、easyECSに入っているデータしか見られない。** 毎晩の同期（`scripts/sync-easyecs-sales`）が easyECS の SQL Server（`t_sell`系）から `ec.sales_*` に写したものだけを集計しており、プラットフォーム側で受注を取得・取り込んでいても、その先で easyECS に入っていなければダッシュボードには出ない → `docs/easyecs-sales-sync.md`

ドキュメントに明記：「**ふるさと納税・自社EC（Shopify）・実店舗・KRK は easyECS に入っていないので含まない**」。**電話・カタログ**（その他受注取り込み）も一覧確認のみでeasyECSには入らないため同様に対象外。**Temu・LINEギフト**は easyECS 側の対応状況（`mall_cd`）次第で、プラットフォーム側のコードだけでは分からない（→ easyECS 側で確認が必要）。

先方の要望は、この**5チャネル（Temu／LINEギフト／Shopify／ふるさと納税／電話・カタログ）を優先的にeasyECSへ入れること**。

### 実は既に段階導入プランがある

[[変換器構想とMDC出力]]には、まさにこの5チャネルをMDC出力経由でeasyECSへ流す**段階導入順**がすでに設計されている（リスクが低い順）。

1. **電話・カタログ**（月数件・返却先なし・金額の重要度低）
2. **ふるさと納税**
3. **Shopify / LINEギフト / Temu**

> 今回の「優先的に入れたい」という要望は、**この既存プランをいよいよ実行する話**として受け止めてよさそう。ただし下記の通り前提の食い違いが1つ残っている。

### ⚠️ ふるさと納税を巡る記録の食い違い（要すり合わせ）

- [[変換器構想とMDC出力]]の段階導入プランは「ふるさと納税は手動受注取込→MDC出力でeasyECSへ流す」ことを前提にしている
- 一方、2026-09-16の実際の打ち合わせでは「**ふるさと納税は受注ソフトに乗せず、Excelの受発注数量ボードで管理している**」「**そもそもeasyECSに入れる前提がない**」ことが判明し、[[2026-09-16 打ち合わせ議事録]]の「既存ノートとの差分・要確認」②として**[[変換器構想とMDC出力]]側の線を引き直す必要がある**と記録されていた
- **この見直しはまだ反映されていない**（[[変換器構想とMDC出力]]は09-17更新のまま、段階導入順も変更なし）
- 今回「優先的に入れたい」という要望が出たことで、**「Excelボードのまま残す」ではなく「プラットフォーム（easyECS経由）に取り込む対象にする」で決着**と見てよいか、当日確認する

### 各チャネルの現状

- **電話・カタログ**：2026-09-16の議事録では「すでにeasyECSへ手入力で対応・件数少なく問題ない」とされていた → [[2026-09-16 打ち合わせ議事録]]。今回改めて優先チャネルに挙がっているため、運用が変わったのか認識の食い違いかを確認する
- **ふるさと納税**：上記の食い違いに加え、**「枚数管理」の実体が未解明**（[[変換器構想とMDC出力]]「次のアクション」：「何を1枚と数え、商品SKUとどう対応するか」。2026-09-15にポータル横断調査を実施したが未解明のまま → [[ふるさと納税の取扱い]]）。ここが決まらないと変換器（MDC出力）が書けない
- **Shopify**：プラットフォーム側のAPI連携は実装済みだが、easyECSへの取込が止まっている（🟥断絶）→ [[受注機能（旧 EC Channel Console）]]
- **LINEギフト**：出店者向けAPIの仕様書入手を2026-09-16に依頼していたが、「仕様は出店後に管理画面・案内資料で確認するもの」とされ、先方側での入手が進んでいない → [[LINEギフト - API 受注リファレンス]]。**入手できなければ受注CSV（Shift_JIS）の手動取り込みで代替する方針が既にある**ため、これ以上は待たずに手動取込側で進める
- **Temu**：プラットフォーム側のAPI連携は実装済み（2026-09-16、実データ未照合）。easyECSへの取込方法は未検討

### 打ち合わせでの確認事項

- ふるさと納税を easyECS 経由に取り込む対象にしてよいか（上記の食い違いの決着）
- 5チャネルの優先順位（段階導入プランの順でよいか）
- それぞれ「自動連携（API・MDC出力）」と「手動CSV取込」のどちらで進めるか
- 実施スケジュール（特にLINEギフト・Shopifyは、先方からの情報待ちをやめてこちらで日程を決めて対応する旨を伝える）
- ふるさと納税の「枚数管理」の実体（ヒアリングできるならこの場で）

**確定したらこのノートではなく [[変換器構想とMDC出力]]・[[テーマ1 - 受注チャネル統合とツール複数人化]] を更新する**（vaultの同期ルール：判断が変わったときは正本を直す）。
