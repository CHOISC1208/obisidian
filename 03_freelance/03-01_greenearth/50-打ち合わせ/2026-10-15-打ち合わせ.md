## 1. 現システムの概要

全体向け30分。**一番伝えたいのは「2つのシステムが何で、なぜ分かれているか」**。技術の話は出さず、「入力する場所」と「考える場所」で説明する。

### 1-1. 2つの立ち位置

|       | **choi-tone**（入力の窓口）                        | **green-earth-platform**（業務の頭脳） |
| ----- | ------------------------------------------- | ------------------------------- |
| 一言で   | 散らばったExcel入力を1画面に集める                        | 集めたデータを使って計算・計画・分析する            |
| 役割    | 人が入力して**貯める**ことが目的                          | 貯めたデータで**業務を回す・判断する**           |
| 現場での顔 | 店舗別受発注、売上実績、棚卸し、簡易原価計算など                    | 製品企画書（商品マスタ）、原価、生産計画、チェックメニュー   |
| ログイン  | Google アカウント（許可ドメイン制限）。入れない人はID／パスワード＋二要素認証 | ID／パスワード＋二要素認証（全員必須）            |
| 設計の優先 | 入りやすさ（小さい変更を頻繁に）                            | 守りやすさ（業務への影響が大きいので慎重に）          |

使い分けの基準は [[プラットフォーム選定の判断軸]]。**「集めるだけで終わるか／集めたものを使って何かを動かすか」**。

### 1-2. 2つをつなぐもの

```
choi-tone（入力）                      green-earth-platform（計算・計画）
 店舗別受発注 ver2 ──商品を選ぶ──▶  製品企画書（商品マスタ）  ◀── 生産計画
 簡易原価計算   ──材料を選ぶ──▶   ・卸価格・ケース入数          ・生産単位／個数換算
                                    ・生産方法（工程）            ・実績／達成率
                                    ・原材料・梱包材・人件費 → 原価
```

- **商品マスタは1つ（green-earth-platform の製品企画書）**。choi-tone の受発注はここから商品・卸価格・ケース入数を読む。だから**製品企画書の入力漏れが、そのまま発注できない商品になる**（現に「ケース入数／卸価格が未登録の商品は発注できない」仕様にしてある）
- choi-tone 側にも店舗・社員の簡易マスタがあるが、これは現場の簡易入力用。正式なマスタは platform 側

### 1-3. 4つの順序（変えない）

①商品マスタ → ②生産の可視化 → ③在庫 → ④経営ダッシュボード。**現場が楽になる下流から作り、そこで貯まったデータが経営判断を支える**。

現在地（2026-10-13 時点のコードから）:

| 領域 | 状況 |

| 製品企画書（商品マスタ） | 稼働中。配合・アレルゲン・梱包材・人件費／その他・編集履歴まで入る |
| 原価 | 仕入実績CSV取込、手入力単価、価格推移（値上がり順）まで。原価は商品ごとに出る |
| チェックメニュー | 梱包材・人件費／その他・原材料マスタの入力漏れを一覧し、その場で直せる |

## 生産計画の流れ（説明資料）

> 「生産計画」＝ green-earth-platform の `生産計画` グループ（`/production-plan/*`）。**紙・ホワイトボードの運用を残したまま、計画づくりと実績の記録だけをシステムに載せた**もの。誰が何を担当するかは**システムでは管理しない**（紙に手書き）。

### 全体の流れ

```
 ① 商品マスタ         ② 計画を作る          ③ 印刷          ④ 現場で割付         ⑤ 実績を記録          ⑥ 実績を見る
 製品企画書に     →  商品・予定数量・  →  日付を選んで  →  担当者欄に手書き  →  日ごとに実際の   →  達成率・過不足を
 生産単位などを       期間を登録            A4で印刷         （紙のまま）          数量を入力           期間・工程で集計
```

### ① 商品マスタ（前提）

製品企画書の「主要情報」に、生産計画で使う**3項目**を入れておく。ここが入っていないと、単位換算が出ない。

| 項目 | 例 | 使いみち |
|---|---|---|
| 生産単位 | 本、袋、箱 | 計画の数量はこの単位で入れる |
| 個数換算 | 1箱＝12個 | 計画・実績を「個」に直して表示 |
| ケース入数 | 1ケース＝何個 | 「個」をさらに「ケース」に直して表示 |

あわせて**生産方法（＝工程テンプレート）**を商品に紐づけておくと、計画づくりで工程が自動で出る。

### ② 計画を作る（`/production-plan/plan`）

- 商品を選ぶ。選び方は**検索**、または**製造拠点 → 工程テンプレート → 商品**のドリルダウン
- 入れるのは、**予定数量・開始日・終了日・メモ**（シンプルに保つ：9/10 の決定）
- 2つのモード:
  - **通常モード**: 1日＝1行
  - **工程モード**: 工程ごとに期間を持つ（例：仕込み 10/20〜21、焼成 10/22）。「＋工程を追加」でその場で足せて、マスタにも登録できる
- 一覧は既定で**今日以降**を表示。予定数量は一覧から**直接書き換え**（保存前に「変更前→変更後」の確認が出る）。作成者も表示
- 「ザラッと複数日登録」は、同じ商品を連続して作る場面が少ないので**作らない**（9/10 の決定）

### ③ 印刷（`/production-plan/print`）

- **日付を切り替えて**表示・印刷。担当者欄は**空欄**（手書き用）
- 計画と数量（生産単位／個数／ケース換算つき）が1枚で見える

### ④ 割付は紙で

人×日×工程の割付は**現場が紙・ホワイトボードで行う**。システムは担当者を持たない（なりすまし・入力負担・欠員時の組み替えの重さを避けるため。以前の「生産オーダー」系は担当者管理があって重く、**現在はサイドバーでグレーアウトして並行停止**している）。

### ⑤ 実績を記録（`/production-plan/actuals`）

- 画面は**「製品｜予定｜実績｜過不足｜達成率」**の固定列。日ごとに**日計行**が付く
- 複数日にまたがる計画も、**日ごと**に実績を入れられる（同じ日に入れ直すと上書き）
- 入力単位は**個数かケース**（端数のケース、例：0.5ケースも可）
- 既定は今日以降。期間を切り替えれば**過去分も記録**できる
- 絞り込み: 期間・工程・状態（**予定どおり／予定≠実績／未記録**）、複数選択可

### ⑥ 実績を見る（`/production-plan/results`）

- 上部に**KPI**: 日別平均達成率／期間の達成率／生産数／過不足／**記録率**（今日までの計画のうち実績を入れた割合）
- **日別達成率のグラフ**（100%線あり、未満は注意色）と**工程別集計**
- 下部は閲覧専用の実績一覧。既定は直近7日間
- 月ごとの経営の場で実績を見る運用を想定（9/23）

### 実績が貯まると何ができるか（次の一手）

- **人件費の按分**: 9/23 に「生産計画の実績をもとに荷重平均で各製品へ按分」と決定。まず70点で進める。→ 原価の人件費が一律配賦でなくなる（[[PRJ-04-経営用ダッシュボード]]）
- **在庫との連携**（フェーズ③）: 店舗在庫から生産数量を提案する。いまの数量は「発注データと経験」で人が決めている。計画にメモ欄を持たせてあるのは、後でこの根拠を接続するため
- **PPM分析・商品カルテ**: 売上と生産の実績から商品ごとの推移を見る

## 生産計画 意見交換の問い

説明の後、**「いまの運用に近いか／負担が増えていないか」**を聞く。

1. **計画は誰が・いつ作るか**。週の頭にまとめて入れるのか、前日に直すのか。変更はどのくらいあるか（欠員・在庫状況による当日変更）
2. 計画を入れる作業は、紙に書くのと比べて**手間が増えたか減ったか**
3. 印刷した紙に**足りない情報**はないか（担当者欄のほか、材料・納品先・メモなど）
4. **実績は誰がいつ入れるか**。作業の合間か、終業後にまとめてか。個数入力かケース入力か、どちらが自然か
5. **単位**の運用: 生産単位・個数換算・ケース入数は商品ごとに正しく入っているか。入っていない商品はどれか
6. 工程の粒度は**今のままで十分か**（簡素化案：工程の簡素化／担当者入力の省略／中間製品のみ登録 → [[PRJ-02-生産状況の可視化]] の未確定）
7. 達成率や過不足の見せ方は、**経営の場で使える形か**。製造スタッフにとって、見られること自体の抵抗はないか
8. 「詰め放題」など**不定形商品**、プレミアム5フレーバーのような**1つの生地から複数に派生する商品**は、どう計画に載せたいか（[[現在の生産計画の作り方]] の論点）
9. 店舗配送タスク（遠鉄・横浜など）を**計画に載せたいか**。載せるなら受発注との連携が要る

### 先に認識しておくこと（言われそうな指摘）

- **担当者を入れられない**ことへの不満が出る可能性がある → 紙運用に一本化した理由を説明し、「欲しいなら何のためか」を聞く
- 実績の**修正履歴は持たない**（上書き）。計画の数量変更は確認ダイアログのみで、履歴は残らない（製品企画書の編集履歴とは別）
- 作業時間（実績の時間）は**現状のシステムには入っていない**。人件費の按分は「計画の実績数量」ベースで考えている点に注意
