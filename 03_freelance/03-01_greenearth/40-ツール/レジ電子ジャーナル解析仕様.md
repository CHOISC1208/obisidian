# レジ電子ジャーナル（.sjl / .euc）解析仕様

株式会社Green Earth の店舗レジが1営業日ごとに出力する電子ジャーナル（レシート控えの全記録）を、
取引テーブルと明細テーブルに変換するための仕様。2024-08-01 分のファイルで検証済み。

## 1. ファイル概要

| 項目 | 内容 |
|---|---|
| ファイル名 | `YYYYMMDD.sjl`（Shift_JIS版）/ `YYYYMMDD.euc`（EUC-JP版）。中身は同一 |
| 使うファイル | **`.sjl` を正とする**（`.euc` は使わない） |
| 文字コード | cp932（Shift_JIS）。UTF-8 → cp932 → euc_jp の順に試してデコードする |
| 改行 | CRLF |
| 単位 | 1ファイル = 1営業日。レジの開設〜精算〜閉設までの全レコードが入っている |

### 最重要の注意
- **必ず先に文字列へデコードしてから行を解析すること。** Shift_JIS の一部の文字（ソ・表・能など）は
  2バイト目が `0x5C`（`\`）なので、バイト列のまま `\` を探すと壊れる。
- 本文の行末にある `\` は「レシート行の続き」を示す記号。デコード後に末尾の `\` 1つを除去し、右側の空白を trim する。
- 金額の前の `\\`（バックスラッシュ2個）は円記号（¥）。金額パターンは `\\\\(-?[\d,]+)`（正規表現リテラル上は4個）。

## 2. レコード構造

ファイルは「ヘッダ行 + 本文行（複数）+ 終端行」の繰り返しになっている。

### 2.1 ヘッダ行（レコードの開始）
タブ区切りで14列。正規表現 `^\d+\t\d+\t` に一致する行がレコードの開始。

| 列 | 例 | 意味 |
|---|---|---|
| 1 | 26 | 連番（ファイル内） |
| 2 | 1 | （不明・常に1） |
| 3 | 1 | （不明・常に1） |
| 4 | 4345 | **J番号**（ジャーナル番号。日をまたいで通番） |
| 5 | 1 | （不明・常に1）※店舗/レジ番号の可能性 |
| 6 | 5028 | **R番号**（レシート番号） |
| 7 | 1 | （不明） |
| 8 | 0 | （不明・フラグ） |
| 9 | 0 | （不明・フラグ） |
| 10 | 1 | （不明・フラグ） |
| 11 | 2024-08-01 09:18:50 | **取引日時** |
| 12 | 2024-08-01 00:00:00 | **営業日** |
| 13 | 1 | **種別コード**（下表） |
| 14 | `**** 2024年 8月 1日(木)09:18 #000001 R5028 J4345 *****\` | 印字ヘッダ（本文1行目扱い） |

注意: ファイル内の並びは時刻順・連番順とは限らない（例: 連番5が2より前にある）。**J番号でソートすること。**

### 2.2 種別コード（13列目）

| コード | 意味 | 取り込み |
|---|---|---|
| 1 | 売上（取消・釣準備を含む） | **取引テーブルへ** |
| 2 | 訓練モード（練習会計） | 取引テーブルへ入れるが状態=訓練（集計から除外） |
| 7 | レジ点検・レジ日計レポート | レポートとして保存（検算用） |
| 8 | 店舗精算レポート（店舗日計・累計） | レポートとして保存（**検算に使う**） |
| 11 | キャッシャークローズ | 除外 |
| 12 | レジ開設・閉設処理ログ | 除外 |
| 61 | 領収書発行 | 任意（領収書番号・金額のみ） |
| 70 | キャッシャーオープン | 除外 |

### 2.3 終端行
本文の後に、タブで始まる行（`\t0\t\t...` や `\t1\t\t`）が来る。
`OPT@...` を含む場合、取引の開始時刻と確定時刻が埋め込まれている（任意で利用可）。
解析上は「次のヘッダ行が来るまで」を1レコードとすればよく、終端行は無視してよい。

## 3. 売上レコード（種別1）の本文

### 3.1 例
```
     000001 店舗
                              登録番号　T1080001017992
                        株式会社Ｇｒｅｅｎ　Ｅａｒｔｈ

  P0000000000085 S0011 100gカマンベ－ルリッ \\6,800外8
                       (  10個 x @680)
------------------------------------------------------
                       小計                   \\6,800
(外税 8%対象額  \\6,800)外税額          8%       \\544
(買上点数         10点)合計                   \\7,344
                    (税率 8%対象額            \\7,344)
                    (内消費税等 8%              \\544)
                       お預り                 \\7,355
                            (内消費税等      \\544)
                       お釣り                    \\11
                     外8,内8は軽減税率対象商品です。
```

### 3.2 行パターン（trim後の行に適用）

| 対象 | 正規表現 | 取り出す値 |
|---|---|---|
| 商品明細 | `^(訓)?\s*P(\d+)\s+S(\d+)\s+(.+?)\s*\\\\(-?[\d,]+)(外\|内\|非)?(\d+)?$` | 訓練印, PLUコード, 分類S, 商品名, 金額, 税区分, 税率 |
| 数量 | `\(\s*(\d+)個\s*x\s*@([\d,]+)\)` | 直前の明細の数量・単価を上書き |
| 売価変更 | `売価変更\s+@([\d,]+)\s*→\s*@([\d,]+)` | 直前の明細の元売価 |
| 小計 | `^小計\s+\\\\([\d,]+)` | 小計（税抜） |
| 小計割引 | `小計割引\s+(\d+)%\s+(-?[\d,]+)$` | 割引率, 割引額（負数） |
| 外税 | `外税額\s+(\d+)%\s+\\\\([\d,]+)` | 税率ごとの外税額（8%/10%） |
| 合計 | `\(買上点数\s+(\d+)点\)合計\s+\\\\([\d,]+)` | 買上点数, 税込合計 |
| 現金 | `^お預り\s+\\\\([\d,]+)` | 支払方法=現金, 預り金 |
| お釣り | `^お釣り\s+\\\\([\d,]+)` | お釣り |
| クレジット | `^ｸﾚｼﾞｯﾄ\s+\\\\([\d,]+)` | 支払方法=クレジット |
| 電子マネー | `^電子マネ－\s+\\\\([\d,]+)` | 支払方法=電子マネー（「－」は全角ハイフン） |
| コード決済 | `^ｺｰﾄﾞ決済\s+\\\\([\d,]+)` | 支払方法=コード決済。後続行に `PayPay` などのサービス名、決済番号、POS取引番号 |

- 明細の数量は、数量行がなければ1。数量行があれば明細行の金額は「数量×単価」の合計額になっている。
- 「ｸﾚｼﾞｯﾄ」「ｺｰﾄﾞ決済」は**半角カナ**、「電子マネ－」の「－」は全角。表記揺れに注意。
- 支払が複数（併用）の可能性がある。支払行は配列で持つのが安全。

### 3.3 取引の状態判定（優先順）
1. 種別コード=2、または本文に `訓練` を含む、または明細行が `訓` で始まる → **訓練**
2. 本文に `取消しました` を含む → **取消**（合計行がなく、小計までしか出ない）
3. 本文に `釣準備` を含む → **釣準備**（つり銭の準備金。売上ではない）
4. それ以外 → **通常**

売上集計は **状態=通常 のみ** を対象にする。

### 3.4 既知のクセ
- **商品名が途中で切れる**: 数量入力がある明細などは、桁幅の都合で商品名が切れる（例: `100gカマンベ－ルリッ`）。商品の識別は必ず **PLUコード** で行い、名前は商品マスタから引く。
- 商品名には全角・半角カナ・長音の代わりの「－」が混在する（例: `パイン&クリ－ムチ－ズ`）。
- PLUコードは先頭ゼロ付きの13桁。**文字列として扱う**（数値にするとゼロが落ちる）。
- 小計割引はレシート単位で記録される（明細には配分されていない）。
- 税区分は `外8`（外税8%・軽減税率）、`外10`（外税10%）など。

## 5. 検算（取り込みのたびに必ず実施）

同じファイル内の **種別8「店舗日計レポート」「取引明細」**（その日の最後に出ているもの）と照合する。
営業日の朝に出ている同名レポートは**前日分**なので、**時刻が一番遅いもの**を使う。

| レポート上の項目 | 照合する計算 |
|---|---|
| 税込合計 | 状態=通常 の total の合計 |
| 総売上 | 状態=通常 の明細 amount の合計 |
| 純売上 / 税抜合計 | 総売上 − 小計割引の合計 |
| 客数 | 状態=通常 の取引件数 |
| 点数 | 状態=通常 の item_count の合計（＝明細の qty 合計） |
| 値下合計 | 状態=通常 の小計割引額の合計（絶対値） |
| 現金売上 / ｸﾚｼﾞｯﾄ売上 / 電子マネー売上 / ｺ-ﾄﾞ決済売上 | 支払方法ごとの total の合計 |
| 取消回数 | 状態=取消 の件数 |

レポートの金額は `.......122,953` のようにドット埋めされているので、`[\d,]+$` で末尾の数字を取る。
件数と金額が2行に分かれている項目（例: 現金売上の件数行 → 次行が金額）がある点に注意。

## 6. 実装手順（推奨）
1. ファイルをバイトで読み、UTF-8 → cp932 → euc_jp の順でデコード。
2. 行に分割し、ヘッダ正規表現でレコードに区切る。本文行は末尾の `\` を1つ除去して右trim。
3. 種別コードで振り分け。1・2は取引として解析、8はレポートとして保持。
4. 取引ごとに3.2のパターンを上から順に当てて値を抽出。明細は直後の数量行・売価変更行で補正。
5. 状態を判定（3.3）。
6. J番号でソートし、(business_date, j_no) をキーに upsert（同じファイルの再取込で重複させない）。
7. 5の検算を実行し、NG なら取り込みをロールバックして差分を報告。
