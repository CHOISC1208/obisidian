# APP No.11 許可申請（仮組み）

| 項目 | 値 |
|---|---|
| リスト内部名 | `PermissionRequests` |
| 表示名 | 許可申請 |
| 定義 | `template/20_requests/_pending/11_permission-request.xml` |
| 要望部署 | 購買G ／ 元重要度: **高** |
| 別紙 | **P1〜4（未入手）** |
| 状態 | 🟨 **仮組みのまま適用されている**（`enabled:true`） |

> [!warning] このAPPは要件が確定していない
> 別紙 P1〜4 が未入手のため、**一般的な業務知識で仮組みした骨子**にすぎない。
> 実際の要件と乖離している可能性が高く、**別紙入手後は列定義ごと作り直す前提**で扱うこと。
>
> なお SPFx の `requestTypes.ts` には**含まれていない**ため、申請ポータル画面にタイルは出ない。
> リストだけが存在している状態。

## 3つの宙ぶらりん

このAPPは判断が3つ止まっている、このプロジェクトで最も不安定なノート。

### 1. 「No.7 へ統合」の回答に従っていない

> [!important] 2026-08-17 の回答と、こちらの判断が食い違っている
> **先方の回答**: 「No.7（年休申請）へ統合」
> **こちらの判断**: 社内判断で**統合せず独立案件として維持**した。そのため
> [[申請ポータル - APP No.07 年休申請]] の休暇区分に「出張」「直行直帰」を含めていない。
>
> `apply-order.json` も `enabled:true` のまま変更していない。
> **この判断が先方に伝わっているかは未確認。** → [[05 要確認事項]] V-3

### 2. `_pending/` なのに適用されている

`_pending/` 配下の4本のうち、**このファイルだけ `enabled:true`**。
他3本（実印・旅費・付与基準）はすべて `enabled:false`。

結果として、**要件未確定のリストが先方テナントに存在している**状態になっている。

### 3. 別紙が来ない

購買G案件（No.11 / No.12 / No.13 / No.15）はすべて別紙 P1〜P11 に依存しており、
**2026-08-07 から一度も提供されていない**。→ [[04 関係者と意思決定の構造]]

## 仮組みの列（実際の要件とは無関係の可能性が高い）

| 内部名 | 表示名 | 型 | 備考 |
|---|---|---|---|
| `Title` | 件名 | Text（必須） | |
| `PermissionType` | 許可種別 | Choice | 時間外労働 / 特別休暇 / 備品持出 / その他 |
| `Details` | 申請内容 | Note | |
| `PeriodStart` | 対象期間(開始) | DateTime | |
| `PeriodEnd` | 対象期間(終了) | DateTime | |

> [!warning] この選択肢は推測にすぎない
> 元資料の文脈（カレンダー反映・プライバシー論点）からは
> **外出・出張・休暇等の勤務に関する許可申請**と推定される。
> しかし仮組みの `PermissionType` は「時間外労働 / 特別休暇 / 備品持出 / その他」で、
> **推定した業務内容とも一致していない**。別紙入手後に全面的に作り直すこと。

## 元資料から読み取れる狙い

- リモート・スマホ対応、データ管理、**カレンダー反映**
- スピーディな処理、紛失防止、督促、進行・状況確認、ペーパーレス

**承認後に部署共有カレンダー（M365 グループ予定表 or SPO カレンダー）へ予定を自動作成する**ことが
この案件の本体である可能性が高い。単なる申請リストではない。

## 最大の論点: 共有カレンダーの公開範囲

元資料でも指摘されている、本件最大の論点。

| 案 | 内容 | 評価 |
|---|---|---|
| A | 誰でも閲覧可（詳細まで） | 利便性最大・プライバシー懸念 |
| **B** | 誰でも閲覧可（表示は「外出」「休暇」等の**区分のみ**、事由は非表示） | **バランス案。まずこれを軸に検討推奨** |
| C | 役職者のみ閲覧可 | 「不在が分からない」デメリット大 |

進め方（元資料の方針を踏襲）:

1. 関係者へヒアリング（実際にプライバシー侵害と感じている人がいるか）
2. **「見られないことのデメリット」**（連絡・業務調整の支障）も併せて周知
3. 案Bをベースに表示項目を最小化して合意形成

> [!info] No.7 の「年休カレンダーの公開可否を選択制に」と同じ論点
> 2026-08-27 に年休申請でも同種の依頼が出ており、**どんな画面を指しているのか掴めず実装できないと
> 判断している**。No.11 と No.7 のカレンダー要件は同じものを指している可能性がある。
> 別紙が来たら**まとめて整理すべき**。
