# Copilot用プロンプト集（年休申請フロー）

親: [[00 MOC|ケーテック株式会社 MOC]] ／ 設計図: [[30-プラットフォーム/powerautomate/Power Automate フロー設計図（簡易承認方式）]]

> [!info] このノートの役割
> Power Automate の Copilot に「言葉で指示して」フローの**土台**を作らせるためのプロンプト。
> 設計図(簡易承認方式)の3ステップを、3回に分けて指示する。Copilot の出力は下書き扱いで、
> **必ず手で確認・修正する**(GUIで作った内容を正とする)。
>
> 対象サイト: `https://ktec19950401.sharepoint.com/sites/s-portal_ver10.0.4`
> 対象リスト: 年休申請(URL `Lists/LeaveRequests`)。**このサイトに同名リストがあることは未確認**(ソース上の定義から推定)。

## Copilotに任せられない部分（手作業で足す）

- 環境変数(`SiteUrl`・リスト名・チャネルID)への置き換え。Copilot の出力はサイトURLが直書きになる
- 編集ロック(REST `breakroleinheritance`)。骨組みは出せても、URL・ロール定義IDは手で直す
- スナップショット対象列の一覧(変数化)
- 接続参照の作り直し(prod では別途)

## プロンプト① 土台（トリガー・承認・書き戻し）

```text
SharePoint Online の次のリストに項目が作成されたとき(項目の作成時)に動くフローを作ってください。
- サイトのアドレス: https://ktec19950401.sharepoint.com/sites/s-portal_ver10.0.4
- リスト名: 年休申請

1. 作成された項目の「Approver」列(ユーザー列)の人を宛先にして、承認アクション「承認の開始と待機」を実行する。
   承認の種類は「承認/拒否 - 最初の応答者」。
   承認カードの件名は「【年休申請】<Title>」、詳細には申請内容(Title、RequestDate、申請者)を埋め込む。
2. 承認された場合: 同じ項目の更新で Status を「承認済」、ApprovedAt を現在時刻、ApproverComment を承認者のコメントにする。
3. 却下された場合: Status を「却下」、ApprovedAt を現在時刻、ApproverComment を承認者のコメントにする。

承認者や個人のメールアドレスをフロー内に直接書かないでください。
Approver 列の値だけを宛先に使ってください。
```

## プロンプト② 起票処理（承認の前に入れる）

```text
上のフローの、承認の開始と待機の前に、次の処理を追加してください。
- トリガーの項目の「作成者」を Applicant 列(ユーザー列)に設定する
- Status 列を「申請中」に設定する
(Applicant と Status は項目の更新アクション1回にまとめてください)
```

別セッションで単独に使う場合は、①と同じ「サイトのアドレス」「リスト名」の2行を頭に足す。

## プロンプト③ エラー時のフォールバック

```text
承認の開始と待機の部分を「スコープ」で囲み、そのスコープが失敗またはタイムアウトしたときの分岐を追加してください。
- 項目の Status を「要手動対応」に更新する(却下にはしない)
- Teams の指定チャネルに「承認者に到達できませんでした。項目ID・件名・リンク」を投稿する
```

## 使うときの注意

- 列の内部名は英語で書いている。Copilot が日本語の表示名で探す場合は表示名(申請者・ステータス・承認者など)に直す。
- 出力後に確認すること: 承認の宛先が `Approver` 列か / Status の値が選択肢と一致するか /
  失敗時の分岐が動くか。**1件テスト申請して通す**。
- Copilot が使えるかはテナントやライセンス・地域で変わる。使えない場合は同じ文章を手順書として手で作る。
- 他のAPPに展開するときは、リスト名・承認カードの件名・スナップショット対象列だけ差し替える。
