# 新しいフローを作る手順(セッションの始め方)

親: [[00 MOC|ケーテック株式会社 MOC]] ／ 設計: [[30-プラットフォーム/powerautomate/Power Automate リスト別フロー設計(簡易承認方式)]] ／ 運用ルール: [[30-プラットフォーム/powerautomate/Claude(FlowAgent MCP)でのフロー生成]]

> [!info] このノートの役割
> 年休申請(No.07)の雛形ができた後、**別のリストのフローを新しいセッションで作り始める**ときの手順。
> 雛形の状態は設計ノート §6 を参照。

## 1. 最初に読ませるもの

1. リポジトリ `k-tec_spo_simple` の `CLAUDE.md`(自動で読まれる)と `flows/README.md`
2. 雛形JSON: `flows/drafts/No07_LeaveRequests_Approval.json`
3. 設計ノート: [[30-プラットフォーム/powerautomate/Power Automate リスト別フロー設計(簡易承認方式)]](リスト別の差分は §3、決定事項は §5〜6)

## 2. 指示の例

```
No.01 仮払金申請の承認フローを作ってください。
雛形は flows/drafts/No07_LeaveRequests_Approval.json、
差分は Vault の「リスト別フロー設計」§3 の No.01 を参照。
サイトは https://ktec19950401.sharepoint.com/sites/s-portal_ver11.0.2、
[TEST] 付き・停止のまま・新規作成のみでお願いします。
```

## 3. 前提として伝えておくと速いこと

- **環境**: FlowAgent の環境は `Default-61c9a7fd-…`(ケーテック default)。新しいセッションは `set_current_env` から始まる。
- **決定済みの仕様**: 通知は Teams(Flow bot のチャット)、承認は2段(1次任意→2次必須)、催促は24時間ごと・平日のみ・最大3回、権限ロックなし、昼食だけ承認なし。
- **実機で分かった落とし穴**: リポジトリ `flows/README.md` の「SharePoint コネクタの落とし穴」(`PatchItem` の `item` はオブジェクト、承認は Webhook 型、トリガーに `splitOn` が必要、など)。
- **リストGUID**: FlowAgent の `list_tables`(コネクタ `shared_sharepointonline`)で引ける。

## 4. 作る前の確認

- 年休(No.07)の実行テストが済んでいるか(2026-10-07 時点: 1次が空の2次のみは成功。1次→2次・1次却下・催促は未テスト)。
- テナント上の `[TEST] No07_LeaveRequests_Approval` がオフになっているか(オンのままだと年休申請リストの新規項目が全部対象になる)。
- 作成前に `preflight_flow` で検証し、`create_flow` は `state=Stopped` で作る。

## 5. 作った後

1. ポータルで宛先・分岐・エラー処理を目視確認(エラー表示がないか)。
2. テスト項目で実行し、実行履歴を確認。
3. 下書きJSONを `flows/drafts/` に保存(個人メールはダミーに)。
4. 設計ノート §6 の「作成状況」表に1行追加。
5. リポジトリはブランチを切ってコミット→PR。
