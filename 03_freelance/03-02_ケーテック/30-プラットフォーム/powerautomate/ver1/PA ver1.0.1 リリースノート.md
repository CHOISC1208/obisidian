# PA ver1.0.1 リリースノート

親: [[00 MOC|ケーテック株式会社 MOC]] ／ 一覧: [[30-プラットフォーム/powerautomate/PA バージョン一覧]] ／ 要望の受付: [[30-プラットフォーム/powerautomate/ver1/PA ver1 要望事項]] ／ 前版: [[30-プラットフォーム/powerautomate/ver1/PA ver1.0.0 リリースノート|PA ver1.0.0]]

> [!info] このノートの役割
> PA ver1.0.0 の実行テスト(2026-10-16)の結果と、そこで見つかった文言の修正の版記録。
> **対応サイト**: `s-portal_ver11.0.6`(変更なし)。

## 実行テスト結果(2026-10-16、本人が実施)

| リスト | 結果 | 備考 |
|---|---|---|
| 勤怠申請 | 承認済になった | 通知文に旧名「年休申請」が残っていた(下記で修正) |
| 仮払金申請 | 承認済になった | |
| 慶弔連絡 | 承認済になった | |
| 海外保険加入依頼 | 承認済になった | |
| 休日出勤/振休/代休申請 | 承認済になった | |
| 夜勤申請 | 承認済になった | 1次・2次を同じ人にして実施。1次は条件によりスキップされ、`【2次】`のみ(設計どおり) |

- 確認できたのは、**2次承認のみで承認済になる経路**(6リストすべて)。申請者への Teams 通知が届き、コメント欄に `【2次】` が入り、`Status` / `ApprovedAt` / `ApproverComment` が書き戻される。承認カードの本文(`ApprovalMessage`)も正しく出る。
- 夜勤申請は1次・2次を同じ人にして出した。フローは**1次承認者と2次承認者が同じ人なら1次を飛ばす**(兼任者に2回承認させないための仕様)ため、1次のカードは作られていない。
- **未確認**: 1次承認が実際に動く経路、却下、承認者に届かない場合(`要手動対応` + 管理者通知)、催促。
  別アカウントでのテストが難しいため、2026-10-16 に**未確認のまま PA ver1.0.1 を採用と判断**した(リスクを承知のうえ)。本番で最初に1次承認ありの申請が出たら、結果を確認する。

## 変更点

| # | 対象 | 変更 | 理由 |
|---|---|---|---|
| 1 | 勤怠申請フロー(No07) | 承認カードの題名・本文、結果通知、管理者アラート、催促の文言を「年休申請」から「勤怠申請」へ修正 | コピー元のフローに旧名が残っており、通知に「[年休申請]」と出ていた(リストは勤怠申請に改名済み) |

## 採用の判断
- 2026-10-16: 6リストすべてで2次承認の経路が動くことを確認し、PA ver1.0.1 として採用。
- 未確認の経路は、本番で最初に当たったときに確認する。問題が出たら PA ver1.0.2 で修正する。

## 影響・仮置き
- 通知文言のみの変更。判定ロジック・宛先・列の参照は変更なし。
- リポジトリ `flows/drafts/No07_LeaveRequests_Approval.json` は修正済みの文言で保存してあり、テナントのフローと一致した。

## 確認チェックリスト(実機)
- [x] 夜勤申請: テスト申請 → 承認済(2次のみの経路)
- [x] 勤怠申請: 結果通知の見出しが「[勤怠申請]」になっている(修正後の再確認は次回の申請で)
- [ ] 1次承認あり(`LeaderApprover` が別の人)の経路 ― **未確認のまま採用**

- [ ] 承認者に届かないとき `Status=要手動対応` と管理者通知 ― **未確認のまま採用**
- [ ] 催促(平日・24時間ごと・最大3回) ― **未確認のまま採用**
