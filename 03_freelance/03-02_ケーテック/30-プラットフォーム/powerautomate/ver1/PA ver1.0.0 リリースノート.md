# PA ver1.0.0 リリースノート

親: [[00 MOC|ケーテック株式会社 MOC]] ／ 一覧: [[30-プラットフォーム/powerautomate/PA バージョン一覧]] ／ 要望の受付: [[30-プラットフォーム/powerautomate/ver1/PA ver1 要望事項]] ／ 設計: [[30-プラットフォーム/powerautomate/Power Automate リスト別フロー設計(簡易承認方式)]]

> 承認フロー(Power Automate)6本の初回リリースの版記録。
> **対応サイト**: `s-portal_ver11.0.6`(SPO側は [[30-プラットフォーム/spo/ver11/ver11.0.6 リリースノート|ver11.0.6]])。

## 変更点

| # | 対象 | 変更 | 理由 |
|---|---|---|---|
| 1 | 6リストの承認フロー | 新規作成・開始(下表) | ver11.0.6 の確定にあわせて、全APPの承認を電子化 |
| 2 | 全フロー共通 | サイトURLとリストGUIDを、フロー先頭のパラメータ `SiteUrl` / `ListId` の1か所に集約。トリガーと全 SharePoint アクションが参照 | 従来は旧サイトの値が PatchItem 等に直書きで、サイトを替えるたびに全アクションを直す必要があった |
| 3 | 全フロー共通 | フロー名から `[TEST]` 接頭辞を外した | リストは本人管理のため本番運用(リポジトリ `CLAUDE.md` の条件も緩和) |

| No  | フロー名                                | 対象リスト        |
| --- | ----------------------------------- | ------------ |
| 07  | `No07_LeaveRequests_Approval`       | 勤怠申請         |
| 01  | `No01_AdvancePayments_Approval`     | 仮払金申請        |
| 02  | `No02_KeichoReports_Approval`       | 慶弔連絡         |
| 03  | `No03_OverseasInsurance_Approval`   | 海外保険加入依頼     |
| 19  | `No19_HolidayWorkRequests_Approval` | 休日出勤/振休/代休申請 |
| 20  | `No20_NightShiftRequests_Approval`  | 夜勤申請         |

共通の動き(勤怠申請の雛形を展開):

1. 項目の作成をトリガーに、申請者・所属部署・`Status=申請中` を設定
2. `LeaderApprover` があれば1次承認 → `Approver` で2次承認(「承認の開始と待機」)。承認カードの本文は `ApprovalMessage`
3. 結果(承認済/却下・日時・コメント)を書き戻し、申請者へ Teams 通知
4. 承認者に届かない・失敗した場合は `Status=要手動対応` + 管理者通知(却下にしない)
5. 催促(平日・24時間ごと・最大3回)

## 影響・仮置き
- 環境変数は未作成。いまは各フローのパラメータで管理しており、サイトを替えるときは6本×2か所を直す。
- 管理者通知先 `AdminAlertEmail` は Flow bot の個人チャット宛(仮置き)。管理者チャネルへの投稿は未実施。
- 6本とも勤怠申請の雛形を展開したもの。**リスト固有の承認条件の差**(段数・任意/必須)は未反映。設計ノートの §3/§5 と照合が必要。
- 権限ロックは当面なし(2026-10-07 決定)。滞留検知・監査ログは対象外。

## 適用時の注意
- 旧サイト(`s-portal_ver11.0.4` 以前)を指す旧フロー(`[TEST]` 付き)は停止・整理していない。旧サイトに新規申請があると動き続ける。
- フロー定義の正はリポジトリ `flows/drafts/*.json`(ソリューションzipは未作成)。
- サイト入れ替え時の手順: リポジトリ `docs/change-patterns.md` / `flows/environment-variables.md`。
