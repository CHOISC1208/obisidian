## C. 資料間の食い違い（黙って上書きしない。確定するまで暫定）

- [ ] **C-1. 画面案の数字が計算式と合わない。** 画面案は「決済51件 → 推奨3人」「32件 → 2人」だが、式（`base ÷ cap × k`、cap=6）なら 51件/時 → 9人、32件/時 → 6人。画面案の数字は 1人あたり約16件/時 の感覚。次のどれかのはず: ①画面の「決済件数」は1時間ではなく別の単位 ②cap の初期値が 6 ではない ③画面は仮の数字。**cap の初期値（A-4）と一緒に決める。**
- [ ] **C-2. 過不足の色。** MVP仕様は「不足＝赤／過剰＝青」だが、画面案3は空き枠を**点線**で表し、過剰を示す青が無い。画面1のタグは「あと1人／ぴったり／イベント予定」で、「多い」状態が無い。
- [ ] **C-3. 業種。** A-2 の推奨は小売先行だが、画面案はカフェ（ランチピークの時間帯）。
- [ ] **C-4. 概算人件費。** MVP仕様の画面3には「週の概算人件費を横に出す」とあるが、画面案3には出ていない。
- [ ] **C-5. 画面案がカバーしていない MVP 画面。** 「はじめる（CSV投入）」「希望の回収」と、「確定・共有」の本体（画面案3は下部の印刷・LINE共有ボタンのみ）。初回体験の決め手（[[01 差別化と勝ち筋]] の①）は CSV 投入直後の画面なので、**最優先で描く**。
- [ ] **C-6. 「LINEで共有」と「LINEで希望回収」は別物。** 画面案3の共有ボタンは配布（出力）。A-3 の推奨で先送りにしているのは希望の**回収**側。出力の LINE 共有は MVP に入っている（機能8）が、実装方式（共有URL か公式アカウントか）は未確認。

- [x] **C-7. 「スタッフはアプリ不要」と交代機能の衝突。** MVP は希望提出も Web フォームで、スタッフ側にログインを持たない設計。「3タップで申請」「候補への通知」「先着で代わる」は、本人を識別できる画面（ログイン or 本人専用リンク）が前提になる。
  → **本人専用リンク（ログインなし）。[[06 入れ替え（交代）機能]]**（2026-11-28、seon ch の指示で細部を決めた。変えるときはここに残す）
- [x] **C-8. 売上が取り込み項目に無い。** 人件費率・予実グラフ（[[07 稼働時間と人件費・予算]]）には売上（金額）が要るが、POS CSV の仕様は「日時・決済件数・点数」。売上の列を任意項目として足すか。
  → **売上を CSV の任意項目に追加。推奨人数には使わない**（2026-11-28、seon ch の指示で細部を決めた。変えるときはここに残す）
- [x] **C-9. 予算と希望の不等号が逆に見える。** 表は 予算人時 > 希望人時 を「予算オーバー」とするが、例（予算38／希望45＝7時間オーバー）は 予算 < 希望。意味から読む向きで書いたが未確認。「希望人時」が何の合計かも〔要確認〕。
  → **例の向きに揃えた（希望人時 > 予算人時 ＝ オーバー）。希望人時＝全スタッフの「希望」の合計〔仮〕**（2026-11-28、seon ch の指示で細部を決めた。変えるときはここに残す）
